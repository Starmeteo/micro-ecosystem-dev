微缩生态 R5 · 尺度、空间与精细度整合包
版本日期：2026-11-25
状态：美术与交互评审资料，供用户确认和后续 Codex 工程审查。

本轮保留像素画风与液态玻璃，重点修正生物相对环境过大、不同生物缺少大小差异、物件空间关系不自然和环境细节不足的问题。

一、先看哪里

可以直接用浏览器打开根目录 micro-ecosystem-r5-preview.html：该文件内嵌预览使用的七张图片，可单独移动后打开，无需联网。

preview-source.html 是使用相对路径的同款源文件。使用它时，解压整个资料包，保留 assets、design、references 与它的相对位置。两个入口都没有连接生态内核。

建议顺序：
1. 在桌面组件中切换林下与浅塘，先看整体构图、生物大小及环境细节。
2. 打开“只看无动物底图”，检查木材、石块、落叶、苔藓和水草之间的尺度。
3. 在“比例与观察”中比较同倍率测量线，使用整体、2×、4×及区域按钮查看局部。放大作用于整幅场景，环境和动物一起变大。
4. 打开“美术素材”，查看新形态研究和沿用的物件造型板。
5. 在编辑工作台中查看属性、环境、生物与内容抽屉的布局。当前不提供真实投放、移动、保存或试运行。

浅色、深色、繁复用于对照不同桌面背景下的玻璃表现。无动物底图、减少透明度、减少动态效果、闲置时钟与恢复均属于设计预览功能；设备时钟与生态世界时间不是同一个读数。

三、本轮尺度约定

主参考深度平面所见宽度：林下 450 mm，浅塘 600 mm。它们是局部画面校准假设，不等于整个生态世界宽度，也不直接改变土壤面积、池体容量或资源库存。

选定的视觉参照：
• 鼠妇主体体长 12 mm。
• 弹尾虫主体体长 1.5 mm。
• 小型陆生蜗牛候选壳宽 6 mm。
• 米虾眼后缘至尾节末端体长 20 mm，额剑和触须另记。
• 水蚤可见躯体长 2 mm，触角和尾刺另记。
• 小型淡水螺候选壳宽 8 mm。

这些数值是设计参照，不是对最终物种的鉴定，也不是所有成年个体统一具有的大小。尺度来源、测量部位、假设、环境档位和投影规则见 design/SCALE_CONTRACT.txt。

960×540 仅为本轮计算示例与审查基准，不是已经批准的引擎分辨率迁移。生成图的文件尺寸、逻辑像素、显示 CSS 像素和设备像素应分别理解。小组件里极小生命接近微点可以接受，局部观察负责补充可辨细节。

四、内容扩充继续保留

design/r5-content-expansion.csv 共 29 个资产族：林下 14 项、浅塘 15 项。除编辑入口、可调整内容、资源映射、模型缺口和验收路径外，新增尺寸测量部位、建议实体尺寸、同层尺度、接触遮挡与生产限制。

29 项是制作与开发矩阵，不是已经生成 29 套可用精灵。新增多实例石木、植物斑块、落叶与观察能力仍需在正式项目中形成完整操作闭环。

六个动物条目的身份：
• 鼠妇、米虾：已有可见功能型的重画与表现改进。
• 弹尾虫、水蚤：既有聚合群体的观察表现提案。
• 小型陆生蜗牛、小型淡水螺：拟新增候选，具体类群与生态模型尚需审查。

同类大小、姿态、花色和幼体不是新增物种。图中较小幼虾也不证明真实成长模型已经完成。

六、资料阅读顺序

1. micro-ecosystem-r5-preview.html：体验本轮画面、局部观察、比例对照和玻璃界面；preview-source.html 为使用相对图片路径的同款源文件。
2. design/SCALE_CONTRACT.txt：尺度、测量、投影、环境标尺与生产规则。
3. design/r5-content-expansion.csv：逐项内容范围、尺度、空间规则及编辑闭环。
4. design/ART_REVIEW.txt：两张主场景的美术复查、目测改善及仍需校准的部分。此文没有宣称严格比例验收通过。
5. design/r5-research.txt：研究来源和参照值的依据。
6. design/r4-glass-spec.txt、r4-content-expansion-notes.txt：继续适用的材质与内容原则。
7. CODEX_R5_REVIEW_PROMPT.txt：可完整发送给 Codex 的独立审查提示词。

补充交接资料：
• design/common-scale.svg：由代码绘制的同倍率测量线，可单独查看，不能当作动物解剖图。
• design/ASSET_INDEX.txt：本轮素材身份、用途和沿用关系。
• design/ASSET_MANIFEST.json：图像文件尺寸及校验信息。
• design/generation-prompts.json：本轮生成说明与提示词记录。
• design/REVIEW_QA.txt：实际检查范围、观察结果与未覆盖事项。
• screenshots：五张实际浏览器预览截图，供界面与美术交接。它们是设计预览截图，不是正式 Windows 项目的运行证明。

浏览器检查包含两主题切换、整体/2×/4×观察与区域切换、底图、三个独立面板、内容抽屉、测量线与换算表、大图原尺寸/Esc返回、三种背景、闲置恢复及减少透明度/动效。检查没有把静态图稿变成真实生态模拟，也不等于 Windows 原生行为验收。

七、交给 Codex 的方式

让 Codex 同时读取当前工程和本资料包，再发送 CODEX_R5_REVIEW_PROMPT.txt 的完整内容。资料中的历史能力与路径需由它对照实际仓库核实，不应直接当作当前生产状态。

第一轮只进行审查并提交：已核对证据、阻断与非阻断问题、尺度/像素/相机方案、素材生产缺口、29 项能力对应、建议实施范围和分批计划。没有阻断也应等待你明确认可 R5 设计与实施范围，不能将本次美术设计授权当成生产代码修改授权。

实施后应分别验收：概念美术、正式素材、交互操作、生态模型与保存状态。本资料包本身不证明真实 Windows 材质、DPI、多屏、生产模型、动画或存档兼容已经完成。

R3 已确定的世界身份、编辑暂停、试运行、草稿、保存与错误恢复语义继续保留。环境、生物和属性需要各自独立内容，场景、观察控件、抽屉和侧栏各自占位，避免重新出现覆盖和多个入口同跳环境页的问题。
