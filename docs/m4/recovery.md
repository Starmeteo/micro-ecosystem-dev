# M4 存档故障与恢复

## 复验环境

使用本地 Windows 上的 Tauri 原生进程。每个故障用独立的世界目录、WebView2 配置、回环调试端口和退出记录。测试只终止由它启动的进程。各次启动同正式桌面应用串行，运行中的实例会被保留。两份由应用真正提交的浅塘检查点分别记录 18.00 L 和 18.80 L，后续各用例从这两份文件的独立副本开始。

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/m4-recovery.ps1 `
  -Executable 'target/release/micro-ecosystem-desktop.exe' -IncludeAutosave
```

测试需要 Node.js 26、安装了 WebView2 的 Windows 和已构建的应用。命令生成 `.local/m4-recovery/run-*`，每个子目录保存实际进程轨迹、断言、截图和隔离存档。`-IncludeAutosave` 使用一秒测试间隔。正式配置默认每 120 个活跃秒检查一次。 [PowerShell 复验入口](../../scripts/m4-recovery.ps1) · [原生断言](../../scripts/m4-recovery.mjs)

## 检查内容

| 情景 | 预期行为与核对内容 |
| --- | --- |
| 提交后强制结束进程，同时存在临时文件 | 冷启动只恢复已提交的 18.80 L。手工注入未完成候选，以及另一份校验有效、序号更高的临时候选。两者不参与恢复。 |
| 最新已提交文件校验失败 | 冷启动回退至 18.00 L，编辑器提示恢复，世界库标为 `recovered`。可写后续检查点，损坏文件原字节保留。 |
| 全部已提交文件损坏 | 世界库标为 `unreadable`，启动提示无法读取，保存被阻止，退出时跳过该世界。 |
| 新格式或缺失定义 | 世界库标为 `unsupported`，恢复报告当前不支持。即使旧检查点还存在，应用仍保护较新的文件。 |
| 独占文件读取 | Win32 文件共享模式由测试进程实际锁住最新版。应用报告无法读取并阻止覆盖，文件和布局的哈希保持。 |
| 写入目录受到占用 | 测试只在临时副本中阻断检查点目录。应用返回保存失败并在编辑器显示，恢复路径后重试成功，已有文件保持。 |
| 自动检查点 | 应用从第 30 步的编辑暂停状态连续生成四份自动提交，保留最近两份及正式检查点。强制结束后冷启动可精确恢复最后一次自动提交的生态与光相。 |

每个常规故障场景核对已有检查点和活动世界索引的 SHA-256。一次实际布局修改验证只改布局文件，随后保存世界验证布局文件哈希保持。强制结束发生在已提交后，候选文件的内容由测试注入。这样可验证提交边界的恢复规则。本实验未切断主机电源，也未对安装盘故障进行破坏性测试。

## 实机结果

Windows 11 构建 `26200` 的发行版通过本轮检查。发行版 SHA-256 为 `85C02123E22E2B28C59998070FC191A4E5342644A9B71EA713B133AC215A4678`。十个隔离进程中有两个按设计强制结束，其余八个都记录了正常的退出提交并以 0 退出。八次正常退出在 WebView2 的 stderr 里各有一条 `Chrome_WidgetWin_0` 注销错误 `1412`，未影响本轮文件与退出检查。 [构建身份](../../.local/m4-recovery/run-20261124-215741-808/build.json) · [退出后的文件哈希断言](../../.local/m4-recovery/run-20261124-215741-808/seal.jsonl) · [WebView2 日志](../../.local/m4-recovery/run-20261124-215741-808/auto-reopen/stderr.log)

- 最新文件校验失败时，实际回退至 **18.00 L、编辑修订 0**。候选半文件和完整候选均被忽略，正常保留 **18.80 L、编辑修订 1**。前一份文件和损坏文件的字节均保持。 [回退截图](../../.local/m4-recovery/run-20261124-215741-808/newest-corrupt/editor.png) · [临时候选测试](../../.local/m4-recovery/run-20261124-215741-808/pending/checks.jsonl)
- 全部损坏、更新格式、缺少定义和独占读取四个场景均返回 `save_blocked`，退出后没有新世界检查点。写入受阻时界面显示 `保存失败`，路径恢复后重试提交成功。 [较新格式退出证据](../../.local/m4-recovery/run-20261124-215741-808/future-format/checks.jsonl) · [写入失败与重试](../../.local/m4-recovery/run-20261124-215741-808/write-failure/checks.jsonl)
- 自动提交序号 **3–6** 由真实计时器触发。保留自动序号 **5、6** 和正式序号 **1、2**。强制结束后冷启动在新运行代次恢复**第 30 步、编辑修订 5、编辑暂停**及同一光相。重新退出时的正式检查点与上一次自动检查点的全部持久生态状态及随机状态精确一致。待平滑衔接的外部日照目标按当前时间重新采样。 [计时器断言](../../.local/m4-recovery/run-20261124-215741-808/auto/checks.jsonl) · [冷启动截图](../../.local/m4-recovery/run-20261124-215741-808/auto-reopen/editor.png) · [精确状态断言](../../.local/m4-recovery/run-20261124-215741-808/seal-auto.jsonl)
