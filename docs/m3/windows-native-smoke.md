# M3 Windows 原生操作验证

在本机用同一 Windows 调试版启动两个独立的应用进程。两个进程使用同一份临时试验数据，各自使用新的 WebView2 配置。通过 WebView2 调试接口操作实际编辑器和组件设置界面，并通过原生 IPC 读取世界状态。两个进程都提交保存退出并返回退出码 0。 [构建标识](../../.local/m3-native-evidence/closure-20261124-214446-257/build.json)

| 场景 | 本机结果 |
| --- | --- |
| 世界库、新建与切换 | 在界面重命名原林下世界，然后从内置浅塘预设新建。浅塘在第 0 步暂停，林下后台推进至第 14 步，再打开林下时已到第 34 步，仍为原运行代次。 |
| 个人预设与空白水域 | 补水后把 18.80 L 的布置另存为个人预设。从该预设新建的世界在第 0 步已有 18.80 L。空白浅塘起始干涸，初始生物按钮不可用，补入 18 L 后可放入初始组合，出现 3 只小虾。 |
| 采用试运行 | 选 10× 后批量推进 20 模拟秒。确认前正式世界保持第 0 步和原状态。采用后正式世界仍为同一 ID，更新运行代次，保持编辑暂停并将第 200 步写入检查点。 |
| 试运行另存与复制现状 | 第二次试运行再推进 60 模拟秒，另存的独立世界处于手动暂停和第 800 步，正式来源仍在第 200 步。复制现状生成新的 ID，完整池塘状态及随机状态相同。 |
| 归档与恢复 | 将第 800 步的复制世界归档后，从归档列表恢复，再次打开保持第 800 步。 |
| 桌面组件独立绑定 | 在组件设置选择林下。在编辑器保持暂停的池塘时，桌面组件实际挂载林下场景和对应标签，所绑定的林下世界由第 35 步推进至第 36 步。 |
| 可见工作区回退 | 在实际 150% 缩放的显示器上，通过原生 IPC 提交一个不存在的显示器身份及相对位置。返回面板完整落在可用工作区内，随后恢复了原位置。 |
| 保存退出与冷启动 | 两次启动间核对正式退出后的最终检查点。重新启动时，暂停中的池塘保留第 800 步、世界 ID、当前光相位、资源、随机状态与编辑修订，运行代次更新。世界库读回 6 个世界、5 个预设，桌面仍绑定林下。 |

## 复验范围

构建后使用 `pwsh -NoProfile -ExecutionPolicy Bypass -File .local/verify/run-m3-native-acceptance.ps1`。脚本会保留已有实例，另建临时数据目录，并在两个试验进程之间记录最后一次已提交检查点。保存退出会更新等待对齐的现实日照目标，模拟时刻的光相位和生态状态保持一致。

显示器验证使用实际 Windows 窗口和构造的失效显示器身份。本次没有接拔第二台显示器、跨屏改变 DPI 或触发真实睡眠。两次进程退出时 WebView2 各有一条窗口类注销警告 1412，已确认检查点写入和退出码均成功。 [首次退出日志](../../.local/m3-native-evidence/closure-20261124-214446-257/begin-stderr.log) · [再次退出日志](../../.local/m3-native-evidence/closure-20261124-214446-257/reopen-stderr.log)
