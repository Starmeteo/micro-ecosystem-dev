# 生态模型与计算契约

版本：交接草案 v0.1。用途：供 Codex 在实现前审查模型是否自洽、是否存在缺口，并作为后续实现与验收的依据。当前交付物不包含已验证的生态模拟程序。

状态标记：**D** 为用户明确决定；**B** 为当前设计工作基线，可在审查中提出有理由的调整；**O** 为尚需确定、研究或校准。数值未确定不等于必须向用户提问，通常由开发者查证、设置有标记的实验参数并完成敏感性分析。

## 1. 目标、范围与可信度

**D-ECO-01**：真实感来自生物与生物、生物与环境之间的相互影响。画面采用细腻的像素风格，主要保持一个精心布置的观察视角。

**D-ECO-02**：首版主题为林下环境与浅水池塘；主题包含典型预设，支持修改后创建世界和自由搭建。

**B-ECO-01**：采用个体、种群、斑块和环境区域混合计算。生态内核独立于绘制帧率运行。一个世界由一份权威状态驱动，多个视图共享它。

**B-ECO-02**：自然切片采用显式开放边界。光、空气条件、降水、外来枯落物或水体交换必须有可追踪的输入定义。封闭容器是后续边界配置扩展，不在首个原型内实现完整化学。

**B-ECO-03**：允许个体死亡、植物衰退和局部种群消失。存档、恢复、投放或更改环境是明确操作；不通过隐藏补充生物或资源保证画面永远繁盛。

**B-ECO-04**：首版为有机制依据的简化模型，不宣称科研预测精度。资料支持机制方向，不自动证明具体公式、参数或虚拟物种组合有效。所有实验参数标识其状态，真实来源、代理物种参数和工程近似分开记录。

**O-ECO-01**：精确物种、初始生态密度、耐受曲线、生长和繁殖速度、空间尺度、模拟步长及数值误差容限尚未校准。它们不是可从参考画直接推断的数值。

## 2. 混合计算粒度

| 对象 | 权威表示 | 必要状态 | 画面对应 |
| --- | --- | --- | --- |
| 鼠妇、米虾等主要动物 | 单个实体 | 稳定身份、位置、阶段、年龄、体量与储备、应激、行为、繁殖过程 | 一只主要动物对应一个实体 |
| 明确成株的蕨类等 | 植株实体 | 身体资源、叶面积或结构阶段、水分状态、损伤 | 植株结构和阶段变化 |
| 苔藓、水草丛、附着藻 | 斑块或植丛 | 所属表面、覆盖面积、生物量、营养状态 | 斑块疏密与范围变化 |
| 跳虫、水蚤等小型动物 | 局部种群或年龄组 | 个体数、总生物量、阶段分布、摄食与繁殖状态 | 可抽样显示；绘制数量不充当种群总数 |
| 真菌与细菌 | 区域功能群 | 生物量及所含物质、底物利用过程、环境响应 | 主要通过分解和环境反馈表达 |
| 土壤、水体 | 环境单元 | 体积、含水量、资源质量、温度及边界条件 | 透明度、水位和植被状态等派生表现 |

种群计数与生物量要同时自洽：减少个体数必须相应转移死亡或移出部分的物质；繁殖产生的个体必须有亲体投入或已声明来源。不得只在画面中增加动物而不更新模型。

**B-ECO-07**：实体在一个世界内以 entityId 唯一标识，完整生态身份为（worldId，entityId）。复制当前世界或创建试运行副本时生成新的 worldId，允许深复制相同 entityId 和随机生成器状态值；两份世界的可变对象、资源池和随机生成器实例不得共享。观察消息另带运行代次，以区分同一世界的加载或恢复实例。

## 3. 空间与单位

### 3.1 生态空间独立于屏幕

建议内部使用米、平方米、立方米、秒及毫克元素质量；水体界面可换算为升，浓度可显示为毫克每升。实施时统一单位适配，禁止在公式中混用升与立方米、小时与秒。具体空间范围属于 O，不因组件变大而改变。

世界记录地形区域、表面、遮阴、覆盖、可通行关系和水域连通关系。画面层级与生态位置分别保存。纯装饰素材不默认影响生态；带模拟属性的物件必须明确其占地、遮阴、阻挡和材料属性。

林下原型采用粗区域或网格。局部水分是实际状态；若尚未计算局部空气湿度，就不能把“覆盖度”直接显示成精确空气相对湿度。

池塘 v0.1 将每个相互连通水域作为充分混合单元。不同水域独立记录资源。水面、底部、植物和附着表面仍具有空间位置，但同一混合单元内部不宣称存在未计算的局部氧或营养梯度。

## 4. 资源账本与开放边界

### 4.1 每个通量必须有来源、去向与处理过程

建议记录过程标识、来源池、目标池、物质量、模拟时段和外部输入标识。详细账本可以在调试模式采样或聚合，正式运行无需无限保留每一笔微小操作。

| 过程 | 来源 | 去向 | 校验重点 |
| --- | --- | --- | --- |
| 摄食 | 可到达的指定食物库 | 同化量、未同化排出物 | 消耗不超过食物现有量；拒食资源不可被消耗 |
| 身体增长 | 已同化储备及可用营养 | 结构生物量 | 限制元素不足时降低增长量 |
| 呼吸 | 可代谢有机碳及已建模氧来源 | CO₂/无机碳边界与代谢结果 | 池塘耗氧受 O₂ 供给约束；碳损失记录一次 |
| 植物生产 | 光、无机碳边界、可利用营养 | 植物或藻类生物量、相应氧通量 | 光提供能量；碳与养分有明确来源 |
| 排出与落叶 | 动物储备或植物组织 | 有机碎屑、按模型定义的可利用营养 | 不以“清理”名义删除资源 |
| 死亡 | 个体、植株或种群的一部分 | 遗体/碎屑资源 | 原身份停止活体过程，物质只转移一次 |
| 微生物利用与矿化 | 可分解有机物与所需资源 | 微生物体、CO₂、可利用 N/P 等 | 同化、固定和释放分别计账 |
| 繁殖 | 亲体投入或种群储备 | 卵、胚胎、幼体等 | 繁殖计数、个体质量和亲体损失一致 |
| 蒸发 | 液态水 | 外界水汽边界 | 非挥发溶质不按比例随水消失 |
| 排水 | 水域中的水和指定随流资源 | 世界外部 | 按混合假设移出对应溶质和可输运物 |
| 加水、加料、投放 | 用户操作或主题边界 | 相应资源库或实体 | 输入量和组成可审计 |

总资源校验使用“当前库存 + 累计输出 − 累计输入”与初始值比较。只对明确跟踪的元素与水量给出误差；不能把未跟踪的气体和沉积过程也声称为闭合守恒。

### 4.2 碳与能量的边界

首版建议显式规定外界无机碳可用条件。光合固碳计为从该边界向生物的碳输入；呼吸和相关矿化碳计入向外界或规定无机碳池的输出。若不实现水中无机碳限制，就标明这一假设，不能随后用该版本预测 CO₂ 限制、pH 或碳酸盐平衡。

光能是外部驱动，能量会耗散；不可把“能量守恒”与“有机物始终不减少”混为一谈。营养储备的能量等价系数与 C/N/P 表示共同定义。

### 4.3 微生物与生物膜只有一份物质所有权

附着生物膜可以由已跟踪的藻类、微生物、碎屑组成。组件可聚合展示这些成分，但摄食时必须从具体成分扣除。不能额外新增一份“生物膜总食物量”又把同一批微生物计入另一个独立食物池。

同一笔分解代谢的氧消耗只能计入一次。若“分解耗氧”已从微生物底物利用计算，通用呼吸阶段不得再对这部分代谢重复收取氧。

## 5. 生物过程与行为

### 5.1 动物个体

每个个体保留摄食对象、有效感知范围、移动能力、生命周期和环境响应定义。行为候选可以包含觅食、移动、停留、躲藏和物种适用的繁殖活动。

行为选择综合自身储备、可到达资源、环境压力与物种偏好；随机性使用该世界可保存的随机状态。个体不会因相机切换而重新选择全部生命状态。

环境响应应考虑强度与持续时间，具体曲线需研究和校准。研究显示鼠妇的微气候响应与物种特性有关，不能把某次实验阈值无条件推广给所有鼠妇。[S1](https://pmc.ncbi.nlm.nih.gov/articles/PMC4525041/)

### 5.2 植物与斑块

生长受光、适宜温度、水分、可利用营养和空间条件共同约束。候选生长量先计算，再按供给不足的资源限制最终同化量。

苔藓、小型蕨类和水草分别配置吸水、营养来源与恢复机制。区分含水状态与损伤；蕨类水分调节能力和干燥后恢复能力是不同特征，不能以统一“补水立即复活”规则替代。[S2](https://pmc.ncbi.nlm.nih.gov/articles/PMC11688535/)

斑块扩展消耗已有生物量或新增生产量，面积增长应与密度、可用基底和物质分配一致。植物遮阴变化要回馈光照暴露计算。

### 5.3 碎屑与分解

不同来源碎屑至少保留 C/N/P 构成与可分解性类别。鼠妇破碎枯叶可以改变后续可利用性，但不能把摄食直接等同于完全矿化。相关研究中，鼠妇对分解的影响会随枯落物状态和微环境变化。[S3](https://ueaeprints.uea.ac.uk/id/eprint/34736/)

微生物利用底物后可增长、呼吸和释放部分矿化养分，也可能暂时将养分固定在细胞中。USDA 的土壤生物资料支持这种储存与释放关系，但其场景数据不能直接充当本项目林下参数。[S4](https://www.nrcs.usda.gov/sites/default/files/2024-05/Rangeland%20Soil%20Health%20Soil%20Biota%20SD-FS-85b%205-9-24.pdf)

### 5.4 水体氧气

溶氧收支涵盖光合产氧、动物/植物/已建模微生物代谢耗氧、水气交换，以及显式进出水携带的氧。光合在无光时停止，呼吸继续；不要再额外添加一项与这些过程重复的“夜间自动扣氧”。氧溶解和生态过程受温度等条件影响。[S5](https://www.epa.gov/caddis/dissolved-oxygen)

充分混合模型按该水域统一氧状态更新生物。水面复氧速率、氧饱和关系与温度范围必须来源明确。允许模型出现过饱和时，应由气体交换过程消散，不以未经说明的硬性截断删除物质量。

## 6. 每个模拟步的建议执行契约

以下顺序属于 B，可依据数值试验调整，但每次改动必须保留资源与复现约束。

1. 在步边界应用已验证的命令，记录外部资源输入和编辑结果。
2. 获取本步世界气候、昼夜与其他外界驱动；不得在内核临时读取真实系统时钟。
3. 更新受编辑影响的遮阴、可通行关系、水域连通与几何派生量。
4. 根据步初状态计算候选输运、摄食、生长、代谢和交换需求。
5. 对共享有限资源统一分配；同一食物、养分或氧气不能被多个过程超额预支。
6. 按分配后的通量更新环境、生物和账本。多个受约束底物必须一起缩放过程，不能扣了一种却未处理另一种。
7. 推进行为、生命周期、繁殖、死亡与相应转移；明确新生个体从哪个步开始参与过程。
8. 更新派生显示值和结构化生态事件。
9. 检查非负库存、有限数值、身份唯一性、资源余额与世界隔离。
10. 在一致边界生成观察快照或持久化检查点。

固定模拟步长为初始方案。步长数值由收敛与性能检查确定；慢速过程分频只能在误差得到检查后加入。试运行加速改变同一套生态与环境时间，不只加速动物年龄。

资源不足的分配规则要有确定性。可采用总需求按权重比例缩放等规则，记录规则版本，避免集合遍历顺序决定长期赢家。极小数值误差容限需与资源尺度关联；不能长期依靠任意归零隐藏负库存。

### 6.1 可用于审查的最小形式

以下是算法契约示意，尚未选定经验函数和校准参数。

- **库存更新**：对每个资源池，下一步库存等于当前库存加所有入账通量，再减所有出账通量。内部转移的两端以同一笔交易提交。
- **浓度换算**：内部浓度可用质量除以立方米体积得到 mg/m³；显示 mg/L 时再除以 1000。零水量分支在除法之前处理。
- **有限资源竞争**：先汇总每种资源的候选总需求，再求供给允许的缩放比例。每个多底物过程取其涉及资源的最严格限制，按同一比例缩放所有输入和输出。是否重新分配剩余资源由确定的规则说明；不得为了提高利用率临时遍历扣减。
- **候选植物生产**：由已选光、温度、水分响应函数得到潜在生产量，再受实际可用 C/N/P 和空间限制。缺少任一必要资源时，实际生产随之缩减；新生组织的元素构成必须匹配扣减量。
- **水气氧交换**：可审查的基础形式为交换系数 × 水面面积 × 饱和浓度与实际浓度之差 × 时间。选择此形式时所有单位必须一致；浓度差可为负，表示向空气输出。交换系数和饱和关系需另行选源，步长须保证输出不过量。
- **压力累积**：使用有定义的暴露响应函数随模拟时间积分，再将其映射为相应的生理变化。评分作为模型内部量，不伪装成实验测量值。

这些形式提供实现约束，不要求 Codex 在首轮审查中立刻提交模拟算法代码。

## 7. 编辑、暂停与连续性

**D-ECO-03**：软件关闭、电脑睡眠或关机期间不做离线生态补算。恢复时沿用保存状态，然后渐变对齐现实昼夜目标。

**B-ECO-05**：季节随世界累计时间推进；日常速度初始采用 1:1，试运行提供加速。具体昼夜目标来源和过渡时长属于 O，由时间设计统一处理。

移动石块会同时更新旧位置和新位置的遮阴、覆盖、通路与附着物处理。**B-ECO-08**：明确标记 attached 关系的苔藓、生物膜等随其基底一起移动；删除基底时，这些附着物一并作为用户外部移出处理，生物量和资源输出原子记账。仅站在表面的动物不属于 attached 关系；如果操作后它没有合法站位，则拒绝整个编辑批次并提示先安置动物，不暗中删除或转移它。附着关系、资源变化和基底操作共同组成一个撤销单位，撤销恢复整批状态。

修改水池形状后，保留已有水量并重求水位；若空间不足，需要显式溢流或阻止提交。挖池操作不能自动生成等体积水。首次创建时以水位设置初始水量，属于另一种初始化语义。首版建议允许新建预设中存在多个独立水域；对已有世界，先支持不改变水域连通拓扑的形状调整。动态分池/合池是否后置由 Codex 审查提出结论，当前没有承诺其首版可用；在明确支持前，应拒绝会改变连通拓扑的编辑批次并说明原因。

试运行副本生成新的 worldId，并深复制环境、生物、待处理过程和随机状态。停掉并丢弃试运行后恢复原世界；采用试运行结果必须是明确命令。暂停和隐藏画面不等价。

**B-ECO-09**：采用结果时采用副本已经推进后的生态时间、资源、生物、随机状态、季节和当前环境节律；正式世界保留自己的 worldId 与原先的运行意图，并创建新的运行代次。试运行标识、加速倍率及试验驱动模式不覆盖正式运行策略；按正式世界配置恢复日常倍率与气候/现实同步驱动，以采用后的当前环境状态连续重定向目标。内部水分、氧气和生物状态通过后续过程响应，不能为切回日常模式而重置。采用前的分支基线比较和原子检查由架构合同规定。

M1 实现最小试运行能力：完整副本、整套模型加速、丢弃并回到原状态。采用结果、另存副本及完整试运行界面在 M3 完成。两主题的完整首版生态内容在 M2 的生态补全任务中落实，不能将 M1 的最小过程当作全部生命过程已经完成。

## 8. 第一版化学范围与显示约束

**B-ECO-06**：水体 v0.1 追踪可利用氮/磷简化库，不拆分 NH₃、NH₄⁺、NO₂⁻、NO₃⁻；不实现精确 pH、硬度、完整硝化/反硝化或沉积物化学。

因此界面不显示这些未实现化学量的伪精确仪表，也不根据它们输出毒性结论。氨形态与温度、pH 等有关，硝化还会消耗氧；当前省略硝化耗氧可能使部分高氮负荷场景的溶氧偏高。[S6](https://www.epa.gov/caddis/ammonia)

首版对持续严重缺氧、长期完全积水的林下土壤或分层水体，应声明模型范围不足。工程行为可以是停止不支持的过程并报告状态，或将场景列为越界；不能继续生成似乎精确的厌氧化学结果。是否实现这些情景应留给后续模型版本。

“生态健康”“水质”等综合指标是带解释的派生展示。其含义只能覆盖已建模因素，不作为现实动物饲养指导或完整生态预测。

## 9. 验证契约

| 检查 ID | 条件与操作 | 应检查的性质 |
| --- | --- | --- |
| ECO-V01 | 固定版本、初始状态、随机状态与环境输入 | 同平台重复运行结果一致或满足预先定义容差 |
| ECO-V02 | 相同模拟时长，不同绘制帧率及无绘制运行 | 生态状态一致；只允许视觉插值不同 |
| ECO-V03 | 摄食、排出、死亡、繁殖和分解 | C/N/P 转移与外部通量一致，库存非负 |
| ECO-V04 | 只蒸发，再加水、排水 | 水量和非挥发溶质关系符合所声明混合规则 |
| ECO-V05 | 共享食物或氧的多个消费者 | 总消耗不超供给；改变遍历顺序不制造优势 |
| ECO-V06 | 移动石头，记录旧新位置 | 暴露、遮阴与可通行关系更新，状态有连续反馈 |
| ECO-V07 | 模拟黑暗与白天 | 光合随光关闭/开启；呼吸单独继续，耗氧未重复 |
| ECO-V08 | 两个不连通水域，仅向其中一个加料 | 另一个资源不变化，除非存在明确交换 |
| ECO-V09 | 保存、关闭、若干现实时间后恢复 | 无离线老化或消耗，恢复随机状态与未完成过渡 |
| ECO-V10 | 缩小步长重复同一受控试验 | 核心结果收敛；校准容差后记录性能成本 |
| ECO-V11 | 降低食物或关闭外来输入 | 结果由规则推导，不能暗中恢复初始库存 |
| ECO-V12 | 零水量、零食物、全部死亡、异常输入 | 无 NaN/崩溃/负数，状态与适用范围清楚 |

定性试验须固定其他因素，并说明条件。例如“遮阴改变蒸发”需要在有蒸发且未被其他限制完全遮蔽的测试条件下验证；不能要求任意环境中遮阴都必然改善所有生物状态。

## 10. 参数管理与审查重点

参数目录见 [parameter-registry.csv](../contracts/parameter-registry.csv)。每个参数记录来源类型、单位、适用对象和校准计划；实施时补充有效范围、模型版本和取值依据。空值表示尚未确定，不能解释成零或默认安全值。来源文章仅支持机制时，不能将其伪装成具体数值来源。

审查时优先回答：

- 是否已有明确的资源所有权、单位与输入输出；是否存在重复计账？
- 生物行为需要的环境差异是否真的计算出来？
- 固定元素比例、充分混合、外界碳供应等近似是否一致？
- 是否把阈值、初始密度或“永久平衡”写成了未经验证的承诺？
- 具体物种选择和参数工作是否可以由资料研究完成？只有会改变产品体验或范围的问题才集中询问用户。
- 当严重缺氧、干涸等状态超出模型范围时，软件是否有可解释行为？

首轮审查只提出问题、建议和必要文档修订；不直接实现本模型。无阻塞问题后，将审查结论和下一阶段计划交给用户，取得开始开发的明确授权。
