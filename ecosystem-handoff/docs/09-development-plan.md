# 开发阶段 任务与交付门槛

版本：0.1 审查草案。日期：2026-11-24。当前阶段：**只审查资料，未授权产品开发**。

## 1. 阶段边界

用户要求先检查缺漏、歧义与需要重新思考的决定，问题处理后才能正式开发。Codex 首轮不得初始化项目、安装项目依赖、编写产品代码或用“技术验证”名义提前做 M0。

审查可以阅读资料和参考图、检查已有文件、核对官方文档、分析方案并创建 `review/` 下的报告。重大产品选择需要用户回答；普通可逆的工程细节给出建议即可。审查通过不等于自动获得开工授权。首次审查后的开工授权按用户实际表达的范围执行：授权整个确认计划时可连续按里程碑推进，授权仅限 M0 时在 M0 完成后停止。范围内的后续阶段无需重复形式批准；重大新取舍、未处理阻塞或超出授权范围时再询问。

### 1.1 审查输出

| 文件 | 必须包含 |
| --- | --- |
| `review/01-audit.md` | 阅读覆盖范围、现有资料一致性、缺漏、冲突、技术/生态/视觉风险、证据与影响 |
| `review/02-questions-and-decisions.md` | 需要用户决定的问题及推荐方案；已可据资料确认的结论；常规工程建议 |
| `review/03-implementation-plan.md` | 修正后的阶段任务、依赖、首个里程碑、验证方式、所需开发环境 |
| `review/04-readiness.md` | `BLOCKED`（资料/技术阻塞）、`NEEDS_DECISION`（产品取舍）、`READY_WITH_TRACKED_WORK`、`READY`；列出未解决事项与当前授权状态 |

若无阻塞，明确写“没有阻塞性问题，等待用户开始开发的明确授权”。若存在问题，按影响优先级分组，避免逐个参数都要求用户凭直觉填数。

## 4. M0 原型基础

授权后，视觉与 Windows 验证可以和无界面内核工作并行。两条工作线使用同一份数据合同，在阶段末汇合。

| 任务 ID | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| M0-01 | 建立工程、版本锁定、基本运行入口与说明 | 审查通过且用户授权 | 在记录的 Windows 环境按说明可重复启动 |
| M0-02 | 制作原创林下视觉样板和可拆素材 | 参考图与视觉规范 | 同一场景在大窗口和小组件中具有清楚层次和可读生物 |
| M0-03 | 实现 Pixi 场景显示、相机和快照消费基础 | M0-01、合同 | 缩放不改变物理大小，视图可销毁重建 |
| M0-04 | 建立 Rust 独立内核的数据与 step 边界 | M0-01、生态范围 | 无界面可接收固定输入并推进示例状态 |
| M0-05 | 验证 Tauri 命令、回执、批量快照与双视图 | M0-03、M0-04 | 一个世界开两个视图，模拟时间不翻倍 |
| M0-06 | Windows 生命周期、尺寸/DPI、基础毛玻璃覆盖实验 | M0-01 | 明确记录实测能力、失败条件和处理方向 |
| M0-07 | 保存/加载最小一致状态，建立新运行代次 | M0-04、M0-05 | 关闭后恢复同一状态，旧快照被拒绝 |
| M0-08 | 测量成本并确定首轮预算 | 可运行原型 | 给出真实设备、场景规模、统计方法及待调整项 |

M0 的示例状态、假数据与临时素材必须显式标注；不能以会动的画面宣称完整生态已经实现。M0 输出应说明哪些模块已真实运行、哪些仍为占位。基础毛玻璃与时钟覆盖只在 M0 验证可行性；完整的鼠标离开延迟、焦点保护与恢复交互安排在 M3，不作为 M1 闭环完成的前置条件。

## 5. M1 林下最小闭环

### 5.1 体验目标

用户从林下预设创建世界，移动一块石头，运行后观察遮阴、水分与鼠妇活动的变化，保存退出，再次打开后继续原有生活状态。

| 任务 ID | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| M1-01 | 固定版本的林下预设与最小内容定义 | M0、林下模型 | 初始资源有单位，外界输入明确，重复初始化可比较 |
| M1-02 | 地表/材料、遮阴、躲藏、可通行与水分 | M1-01 | 移动物件后旧、新位置属性都更新，资源不凭空产生 |
| M1-03 | 鼠妇个体、食物选择、需求与基础生命过程 | M1-02 | 行为能对应记录的环境与自身状态 |
| M1-04 | 有机物、分解者、植物与养分的最小转移 | M1-01 | 摄食、排出、死亡与分解通过账本检查 |
| M1-05 | 选择/移动/笔刷最小编辑、批次撤销、暂停语义 | M0、M1-02 | 一次操作原子提交，预览不污染世界 |
| M1-06 | 从状态到图像的映射和观察记录 | M1-03、M1-04 | 显示真正计算的变化，日志不虚构因果 |
| M1-07 | 完整存档、现实日夜渐变、睡眠恢复 | M0-07、TIME 约束 | 不补算离线，过渡中途保存后仍连续 |
| M1-08 | 最小试运行：深拷贝、整体加速、丢弃 | M1 模型与存档状态 | 调试入口即可；副本有新世界身份，原世界/RNG不受副本推进影响，丢弃可返回原状态 |
| M1-09 | 闭环验收与首轮参数校准 | 上述任务 | 提供资源账本、固定输入结果和 Windows 操作证据 |

第一轮所选植物、动物和过程可以保持小规模；首版双主题目标继续保留。需逐项记录未实现的生命过程与后续任务，不能把范围缩减隐藏在演示中。

## 7. M3 首版交互整合

| 任务 ID | 内容 | 验收 |
| --- | --- | --- |
| M3-01 | 按主题浏览预设、修改另存、空白创建 | 新建世界、保存预设和复制现状具有明确不同语义 |
| M3-02 | 多世界管理与后台运行 | 切换只改变视图绑定，世界各自保持气候与暂停状态 |
| M3-03 | 完整试运行流程、采用结果与另存 | 复用 M1 副本能力；采用核对 fork 基线、保留正式身份/运行意图、恢复日常倍率与驱动；另存生成独立世界 |
| M3-04 | 放大观赏、小组件和离开后时钟覆盖 | 指针/焦点状态无反复闪烁，编辑时不自动遮挡关键操作 |
| M3-05 | 独立时钟与环境组件、自由布局和叠放 | 布局编辑不移动世界物件，多个视图共享一个世界 |
| M3-06 | 多屏和缩放比例下的布局恢复 | 窗口与组件可找回，显示缩放不改变生态物理尺度 |
| M3-07 | 设置、状态说明和错误恢复 | 保存失败、暂停、过载和未建模指标都有诚实反馈 |
| M3-08 | 季节视觉与日常观察整合 | 基于 M2 的真实季节状态映射素材、色彩和观察信息；不另写独立视觉季节时钟 |

一面板内的组件不等于每个组件都需要一个系统原生窗口。是否拆成多个窗口依据用户摆放需求和技术验证决定。

## 8. M4 交付与长期验证

完成固定场景长期运行、资源与数据不变量、多视图反复开关、存档故障恢复、Windows 安装启动与性能验证。交付包含可运行产物、构建说明、已通过/未通过测试、素材来源清单、模型适用范围、已知缺陷和后续任务。

版本的“完成”应由验收记录支持。类型检查、编译通过或浏览器里的操作成功，不自动代表 Windows 休眠恢复、安装和 GPU 兼容性通过。

## 9. 阶段性风险与处理时点

| 风险 | 处理阶段 | 可接受输出 |
| --- | --- | --- |
| 九张参考图丰富程度与可编辑素材制作量 | R、M0 | 视觉样板、素材拆分与工作量判断 |

| 多世界负载与常态功耗 | M0 建基线，M3/M4 复测 | 实际测量后给出预算与过载策略 |
| 内容升级破坏旧存档 | R 设计，M1 起验证 | 版本化定义、旧样本与明确迁移策略 |

## 10. 开发过程中如何反馈

每个阶段结束说明：完成的用户行为、实现范围、修改原因、真实验证证据、尚未解决的问题，以及下一阶段依赖。新增需求先记录到决策与范围文档；重大改变交由用户决定，常规实现问题可自行解决并记录理由。

Git 提交按可解释的任务组织，避免把大量互不相关的修改堆成一个无法审查的结果。无需为了形式制造空提交。资料中的示例 API、目录和参数在落实后应同步更新，防止文档长期保留过时约定。
