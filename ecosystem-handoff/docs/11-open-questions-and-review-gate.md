# 审查、待决问题与开工门槛

## 1. 首次任务

用户要求 Codex 在开发前审查本资料，识别缺漏、矛盾和需要重新思考的事项。首次会话处于 REVIEW_ONLY。允许阅读文件、查看图片、查询官方文档、核对链接和结构、用只读小脚本检查资料、写审查报告。首次不初始化产品工程，不安装产品依赖，不编写生态内核或界面，不制作正式素材，不构建、部署或发布产品。

对明显的文档错字、失效相对链接可在记录后修正。涉及产品规则、范围、生命周期、视觉方向或重要数据语义的修改应先提出建议，不擅自覆盖基线。

## 2. 审查对象

1. 产品目标、两个主题、固定视角、现实同步与离线暂停之间是否一致。
2. 生态编辑、试运行、采用结果、模板另存、世界复制、撤销的准确语义。
3. 主要动物、种群、植物斑块、微生物和环境单元的计算边界是否可实现。
4. 水量、营养、生物量、食物与氧是否具有不重复的来源、去向和竞争规则。
5. 睡眠、应用退出、关闭窗口、后台世界和多视图是否存在歧义。
6. 原图是否全部可读；逐图分析是否与实际画面相符；美术质量计划是否可信。
7. Rust 权威状态、命令与快照、runGeneration、编辑版本、存档恢复的合同是否闭合。
8. 当前技术栈官方文档、依赖兼容性、Windows 能力和性能验证计划是否成立。
9. 首个里程碑的依赖、完成条件和后续扩展是否清晰。
10. 资料中是否存在把示意参数、旧原型或文献机制冒充已验证产品的情况。

## 3. 问题等级

| 等级 | 定义 | 处理方式 |
| --- | --- | --- |
| P0 当前开工阻塞 | 会导致目标错位、关键规则相互矛盾、必要资料不可读或当前阶段无法正确实现 | 明确原因、证据、建议和用户选择；解决前不启动受影响阶段 |
| P1 当前阶段需明确 | 需要在当前阶段实现前明确，通常可通过工程研究或小实验解决 | 指定负责人、默认建议和验收方法；影响体验时提问 |
| P2 后续阶段事项 | 当前可按已记录假设继续，后续到相关阶段再决定 | 加入计划和到期检查点 |
| P3 改进建议 | 不影响当前正确性，可增强体验或维护性 | 记录为可选建议，不借此扩大首版 |

将“缺少已校准生态参数”分解为研究/校准任务，而不是要求用户报出摄食率、扩散系数或真实物种常数。将“美术未完成”分解为样板和素材生产任务，而不是把整份资料判成永远不可开发。

## 4. 用户问题的格式

每个需要用户判断的问题须包含：

- 对应文档位置或决定 ID；
- 目前为何有歧义；
- 默认建议；
- 两到三个实际可选方案及体验/范围差异；
- 不回答会影响哪个里程碑；
- 能否在不损害用户目标的前提下先采用可逆默认值。

优先集中提出最重要的三到五个问题。其余放入报告；若确有更多独立阻塞项，说明为什么需要分批。不要重复询问 Windows、像素风、两个已选主题、离线暂停和已接受技术栈这些已经决定的事项。

## 5. 四份审查输出

| 路径 | 内容 |
| --- | --- |
| review/01-audit.md | 阅读范围、实际查看过的参考图、问题清单、证据、等级、受影响文件、建议 |
| review/02-questions-and-decisions.md | 用户问题、可由开发者决定的事项、采用的可逆假设及后续决定 |
| review/03-implementation-plan.md | 修订后的 M0/M1 范围、依赖、数据合同待补项、Windows/视觉验证安排 |
| review/04-readiness.md | 总体结论、未解决 P0/P1、可进入阶段、待用户开工授权状态 |

如果原图无法打开，明确列出缺失的 REF 编号，不能声称已审查画风。如果工具只允许查看部分资料，说明审查覆盖范围，继续做其他已授权的审查。

## 6. 审查结论

- BLOCKED：资料、工具或技术条件使当前阶段无法可靠推进；先列出开发者可解决的调查与补核工作。
- NEEDS_DECISION：存在影响当前阶段、需要用户取舍的产品选择或关键矛盾。
- READY_WITH_TRACKED_WORK：当前阶段没有未处理的阻塞问题，但有已安排的研究、校准或后续决定。
- READY：当前阶段的目标、约束和实施路径明确。

READY 或 READY_WITH_TRACKED_WORK 仅表示资料具备进入所列阶段的条件，不表示生态模型已校准、性能已通过、Windows 已完成测试或整个项目可以交付。

首次审查完成后停止，向用户报告并等待明确开工指令。用户确认问题答案本身不自动等于授权开始；应明确其是否要求启动 M0。授权后可更新 gate.json 记录真实授权依据与范围，但不能靠自行修改 JSON 生成授权。若用户授权整体确认计划，可在该范围内持续按里程碑执行；若仅授权 M0，则在 M0 完成后停止。不要把首次审查门扩张为每阶段都必须再次询问。

## 7. 当前最值得检查的取舍

这些是审查线索，不是预先认定的阻塞问题：

- “关闭”究竟指关闭一个视图、隐藏至托盘还是退出应用；与后台世界继续运行怎样配合。
- 现实昼夜使用怎样的时间目标，世界季节与该目标怎样组合；是否需要地点信息。
- 1:1 正常速度是否能在用户日常使用中看见有意义的变化；调试加速不能掩盖最终体验问题。
- 素材生产如何同时满足参考画质、可编辑拆分、遮挡和生长阶段。
- 自然切片的水与枯落物输入怎样设置，并让用户知道其来源。
- 当前 Windows 实测环境能支持哪些窗口、DPI、多屏和节能验收。
- 新建时配置多个水域、保持拓扑的形状编辑与运行世界中的动态分池/合池应分别定范围；首版暂缓动态分合池是可审查的默认建议。
- 附着物随基底移动/移出采用同一原子批次，动物占据表面与真正附着关系分开；审查该默认是否覆盖编辑失败与撤销。

审查应提出判断与解决路径，避免只列风险而不给能做的下一步。
