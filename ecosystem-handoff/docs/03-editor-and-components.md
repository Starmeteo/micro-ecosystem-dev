# 编辑器与桌面组件交互说明

版本：审查资料 v0.1  
日期：2026-11-24

本文件把已讨论的创作与观看方式具体化为可审查的操作规则。D 表示用户明确方向，B 表示工作基线或本文件提出的可调整交互建议，O 表示仍需选择或验证。键位、面板位置和延迟时长均属于 B/O，不能冒充已由用户逐项确认。

## 1. 四种工作状态

| 状态 | 用户主要在做什么 | 对世界的影响 |
| --- | --- | --- |
| 观赏 | 看画面、局部缩放、检查状态 | 按世界运行策略推进 |
| 生态编辑 | 修改地形、植物、物件和生物 | B：暂停当前世界，操作经验证后提交 |
| 试运行 | 验证环境配置、加速观察 | B：推进完整副本，原世界保留 |
| 布局编辑 | 调整组件的位置、尺寸、层次和绑定 | 不修改生态地形及资源 |

UX-001（B）：生态编辑与布局编辑应具有显著的工具栏和状态提示。用户能够确认自己正在改“世界内容”还是“桌面摆放”。

UX-002（B）：同一世界建议只允许一个活动编辑会话；其他视图继续显示该世界并提示正在编辑。若实现多个编辑入口，应先定义冲突处理，不能让两个视图各自维护不同的权威状态。

UX-003（B）：暂停原因应区分手动暂停、生态编辑、系统挂起及技术错误。退出编辑仅移除编辑暂停原因，不自动解除用户原先的手动暂停。

## 2. 从主题到世界的创建流程

### 2.1 从预设创建

1. 打开“创建世界”，选择主题。
2. 查看主题的典型预设、生态边界和适用说明。
3. 选择预设，预览主要环境和生物配置。
4. 为新世界命名；默认名称可自动生成，名称不承担唯一身份功能。
5. 实例化独立世界，打开生态编辑器。
6. 用户调整后选择开始生活；若直接开始，使用预设初始配置。

UX-004（D/B）：创建得到新的 worldId，不修改内置预设。复制预设不沿用另一个正在运行世界的年龄和历史。

### 2.2 从空白开始

1. 选择主题与空间范围。
2. 使用主题提供的基础底材、区域和物件建立环境。
3. 添加植物与其他生物。
4. 检查缺少的必要条件。
5. 进入试运行，或者明确开始正式运行。

UX-005（B）：检查结果分为“无法实例化的错误”和“可以运行但存在生态风险的提示”。越界数据、缺失定义等可以阻止创建；可能不稳定的生物配置应解释依据，避免一律禁止用户实验。

空间实际尺寸、气候边界和水体类型是世界配置，不与当前窗口像素大小绑定。

## 3. 编辑器界面结构

建议使用一个主画布与按需展开的工具面板：

| 区域 | 内容 |
| --- | --- |
| 顶部状态区 | 世界名称、主题、暂停/编辑状态、保存状态、试运行入口 |
| 工具区 | 选择、区域笔刷、物件放置、生物放置、删除等 |
| 素材区 | 当前主题适用的底材、植物、物件和生物，可检索与筛选 |
| 主画布 | 当前构图、放置预览、选中轮廓与必要辅助信息 |
| 对象与层次区 | 物件列表、可见性、锁定、被遮挡对象的选择入口 |
| 属性区 | 选中对象或区域的物理与显示属性，单位明确 |
| 底部或可收起诊断区 | 操作结果、生态检查、资源变化、试运行趋势 |

UX-006（B）：主画面优先保留观看空间。诊断信息可收起，核心交互仍须可发现。

UX-007（B）：屏幕坐标、相机坐标和模拟坐标转换统一处理。缩放或拖动画布以后，放置位置、选中范围和笔刷落点保持一致。

## 4. 工具与手势建议

下表是待原型验证的键鼠基线，不要求 Codex 原封不动采用全部键位。

| 操作 | 建议手势 | 注意事项 |
| --- | --- | --- |
| 选择对象 | 左键点击 | 使用可见轮廓或命中区域，并能从对象列表选择 |
| 移动物件 | 拖动已选对象或专用移动柄 | 有预览、合法性提示和提交边界 |
| 平移观察区域 | 中键拖动；可提供空格按住拖动 | 不应同时触发播放/暂停 |
| 缩放观察区域 | 滚轮围绕鼠标位置缩放 | 限制观察范围，保留重置视图入口 |
| 取消当前预览 | Escape | 不自动丢弃其他已提交操作 |
| 撤销/重做 | Ctrl+Z、Ctrl+Shift+Z，可兼容 Ctrl+Y | 仅在适用的编辑上下文生效 |
| 删除选中项 | Delete | 在文字输入框中不触发场景删除 |
| 保存 | Ctrl+S | 明确保存正式世界、预设或试运行副本的目标 |
| 精确移动 | 方向键或属性输入 | 步长有单位；按焦点决定是否移动对象 |

UX-008（B）：快捷键只在应用适当焦点内工作。首版不注册影响其他应用的全局编辑快捷键。

UX-009（B）：首个闭环可先支持可靠单选。多选、框选和成组编辑属于完整首版可评估内容，需要定义共同移动和资源操作语义后再加入。

## 5. 选择、遮挡、层次和锁定

UX-010（B）：选中状态应表现为轮廓、标记或轻量辅助线，避免大面积覆盖生态画面。

UX-011（B）：被前景遮挡的对象可以通过对象列表选中。可增加循环选择重叠对象的手势，但应在工具提示中说明。

UX-012（B）：编辑锁定保护对象免于误操作，不使其脱离生态模拟。隐藏对象用于编辑辅助时，需明确是“仅在编辑器隐藏”还是产品视图可见性。

UX-013（B）：绘制层次不直接等价于模拟高度。把植物调到前景绘制不能让它凭空获得新的水深、遮阴或通行关系。

UX-014（B）：物件的真实尺寸、模拟占地和显示缩放分别定义。日常调整组件大小只改变视图；修改生物或石块实际尺寸需要明确的物理编辑操作。

## 6. 区域笔刷

候选笔刷包括土壤材料、苔藓覆盖、落叶和水域形状等，按主题提供。

UX-015（B）：笔刷至少显示当前工具、范围、作用对象和强度或数量含义。数值名称应说明是覆盖面积、层厚、初始生物量，还是仅视觉密度。

UX-016（B）：一次连续按下到抬起的笔刷行为形成一个撤销单位。工具预览可以连续绘制，权威世界采用明确的提交批次。

UX-017（B）：笔刷受到区域边界和放置规则约束。涂抹结束后报告有效修改，不静默将越界部分写进其他水体或地表。

UX-018（B）：苔藓、植物或落叶笔刷如果参与生态，就需要产生明确的生物量或有机物输入。删除区域也需要记录对应输出。纯装饰笔刷应标记“仅装饰”。

地形与水域笔刷属于较高影响操作。已有水体形状改变时应根据既有水量重求水位；补水、排水或更换水体属于独立操作，不能通过随手改变几何而自动生成水。

UX-049（B）：新建预设时可构造多个独立水域；已有世界暂只允许不改变连通拓扑的形状编辑。预览或提交若将一个水域切成两个，或将两个水域连成一个，应提示该操作超出当前支持范围并拒绝整批。动态分合池列为 O，先审查资源、生物、输入边界与水域身份迁移规则，再决定是否纳入实现。

## 7. 物件与生物放置

### 7.1 放置预览

从素材面板拖入，或选择素材后在画布中放置。预览显示尺寸、锚点和可放置位置。无法放置时说明最直接的原因，例如缺少承托表面、超出水域或与受限物件冲突。

UX-019（B）：图像透明部分不必全部成为碰撞区域；模拟占地、可活动表面和画面精灵应有各自定义。

UX-020（B）：旋转和镜像按素材能力提供。无法自然翻转的光照、方向性植物或结构，不能仅靠任意旋转图片处理。

### 7.2 放入生物

用户选择物种及数量，在合法区域放入。生物的初始生命阶段和状态使用主题默认值或明确设置。

UX-021（B）：添加生物创建新身份，移动已有生物保留其身份和生命状态。显示的渲染点与群体统计须区分，避免将水蚤的代表性点数误当实际总数。

UX-022（B）：对可能不适宜的生物组合给出有依据的条件提示。当前没有建模的适应性因素不应伪装成已通过的适宜性检查。

### 7.3 基底与附着物

UX-050（B）：内容定义明确区分真正附着的苔藓、生物膜等，与仅站在表面上的动物。移动基底时，真正附着的对象随基底移动并保留身份、生物量与相关资源；原位置和新位置的空间属性随同更新。

UX-051（B）：移除基底时，相关附着物一并作为外部输出，和基底操作原子提交、原子记账。撤销恢复完整批次。仅站在表面的动物不因承托关系被当作附着物删除；若移动或移除后动物无合法位置，提示用户先明确安置，或拒绝本次批次。用户可通过明确的安置操作解决，系统不能暗删、重生或悄悄搬迁这些个体。

## 8. 预览、提交、撤销与保存

UX-023（B）：拖动或绘制期间可先显示前端预览；提交后由 Rust 验证。界面须在失败时恢复或保留可修改草稿，并显示原因。

UX-024（B）：一次操作只应提交一次。提交中的重复点击、重试和迟到结果按操作身份处理，不重复创建生物或复制资源。

UX-025（B）：操作提交、生态推进和磁盘保存具有不同状态。只有存储成功后才能显示“已保存”。

UX-026（B）：暂停编辑中的撤销可恢复对应修改；在世界继续运行以后，要回到过去应使用完整检查点。界面不能撤销一个几小时前的石块移动，同时保留期间已经依赖它发生的生态结果。

建议保存状态包括“已保存”“有未保存变化”“正在保存”“保存失败”。错误提示保留重试和查看保存位置等入口，避免只出现短暂弹窗。

## 9. 试运行

试运行是对当前完整状态的独立分支。M1 实现调试级的完整复制、整体加速和丢弃，足以验证隔离与时间；以下完整界面中的采用、另存和结果说明在 M3 集成。

1. 在生态编辑器中启动试运行。
2. 复制环境资源、生物身份与状态、时间、环境驱动和随机状态。
3. 给副本独立的运行身份，界面持续显示“试运行”。
4. 可暂停、整体加速和查看诊断信息。
5. 结束时选择丢弃、另存为新世界，或采用当前结果。

UX-027（B）：原世界在试运行期间保留，并维持开始试运行时的编辑/暂停状态。

UX-028（B）：丢弃副本不影响正式世界的资源与时间；另存新世界获得新 worldId。

UX-029（B）：创建副本时记录正式世界的 worldId、runGeneration、editRevision 和 simulationTick。采用前必须校验这四项均与分支创建时一致；任一改变都不能直接覆盖正式世界，应拒绝采用并提供重新试运行或另存结果的路径。采用形成完整生态状态替换与检查点，正式 worldId 保持不变，分配新的 runGeneration，通知所有视图重新同步。

采用只采纳生态状态、世界时间、随机状态及当前环境节律，不把副本的试运行倍率和试验控制模式写成日常设置。正式世界恢复原有运行意图和日常倍率（当前基线为 1:1）；仍处于生态编辑时继续按编辑规则暂停，离开编辑后依据原用户运行意图恢复。现实同步目标从正式世界的原配置重新取得，从采用后的当前环境节律渐变衔接，不立即跳变内部环境或资源。

UX-030（B）：常规 Ctrl+S 不能把试运行结果悄悄覆盖正式世界。试运行保存操作需明确显示目标。

UX-031（B）：试运行倍率作用于整个相关生态与环境时间线。桌面现实时间保持正常。

## 10. 保存为预设与复制世界

| 操作 | 用户意图 | 保存内容 |
| --- | --- | --- |
| 保存世界 | 下次接着生活 | 当前完整世界状态 |
| 另存当前世界副本 | 保留此刻分支进行不同实验 | 新身份的当前状态副本 |
| 保存为预设 | 将布置作为未来创作起点 | 明确选择的初始方案及初始生物配置 |
| 保存工作区 | 保留桌面摆放 | 面板、组件、世界绑定、尺寸与位置 |

UX-032（B）：保存预设时说明是否包含当前生物分布，如何转换生命阶段与资源为初始配置。首版可先提供单一明确规则，再考虑细化选项。

UX-033（B）：内置预设默认只读，编辑后另存为个人预设。预设、世界和布局的名称可以相同，但内部身份不得混用。

## 11. 组件与面板

### 11.1 组件模型

- 生态组件：绑定一个 worldId 和视图配置。
- 时钟组件：绑定现实时间与显示格式。
- 环境信息组件：绑定一个 worldId 与选择的已实现指标。
- 面板：承载组件，定义布局边界与层次。

UX-034（D/B）：同一个世界可以被多个生态组件观察；它们共享权威状态。创建第二个视图不创建第二份模拟。

UX-035（D/B）：时钟可以放在生态组件区域内，也可以作为面板中的独立组件。调整其位置只修改布局数据。

UX-036（B）：首版组件可先作为面板内的子视图实现。独立原生窗口应对应明确的面板/独立窗口需求，不能默认为每个控件创建一个操作系统窗口。

### 11.2 布局编辑操作

进入布局编辑后，组件显示拖动和缩放控件。支持调整位置、尺寸、层次，选择生态组件所观察的世界，并保存布局。

UX-037（B）：拖动组件时不向内部生态编辑器传递放置操作。时钟等覆盖组件消费自己的输入，空白区域的事件穿透按明确规则处理。

UX-038（B）：建议提供对齐线与可选吸附，允许自由摆放。吸附强度、最小尺寸和超出面板行为通过原型验证。

UX-039（B）：生态视图改变尺寸时保持世界尺度与相机规则。用户可以选择适应画面或裁切观察，不能默默拉伸生物比例。

UX-040（B）：删除生态组件只删除视图。删除世界是单独的操作，应明确它会影响哪些绑定视图与存档。

## 12. 鼠标离开后的毛玻璃与时钟

D：用户期望鼠标离开组件一段时间后覆盖毛玻璃，并显示时钟或其他内容。

建议状态规则：

| 当前状态 | 触发条件 | 下一状态与表现 |
| --- | --- | --- |
| 正常展示 | 鼠标进入，或组件具有键盘焦点 | 保持可交互；按需显示轻量控件 |
| 正常展示 | 鼠标离开，且没有拖动、编辑或键盘操作 | 进入离开计时 |
| 离开计时 | 鼠标返回或重新获得有效交互焦点 | 取消计时，回到正常展示 |
| 离开计时 | 达到配置的延迟 | 平滑进入毛玻璃覆盖，显示时钟/选定内容 |
| 毛玻璃覆盖 | 鼠标进入或用户通过键盘激活组件 | 平滑恢复画面与交互 |
| 任意展示状态 | 进入生态编辑或布局编辑 | 暂停自动覆盖，保持编辑可见 |

UX-041（B）：“离开”针对该组件的有效交互区域；子组件之间移动不应造成反复闪烁。覆盖时钟的区域也属于组合组件的有效范围。

UX-042（B）：延迟与过渡时长是可调参数，首版先通过样板确定默认值。窗口失焦与鼠标离开是不同事件，不能未经说明混用。

UX-043（B）：毛玻璃效果首先针对生态画面内部实现。是否模糊桌面背后的其他窗口属于单独平台需求，不能把两者混为已实现功能。

UX-044（B）：覆盖状态可降低渲染频率，但不改变世界累计运行速度。回到画面时读取最新快照。

UX-045（B）：世界被暂停或存在保存错误时，覆盖层仍可提供简短状态提示，避免完全掩盖重要问题。

## 13. 窗口、托盘与退出语义

关闭视图、关闭主编辑窗口、最小化、隐藏到托盘和退出进程应分别定义。

| 动作 | 必须保证的语义 |
| --- | --- |
| 关闭一个观察视图 | 解除该订阅，世界是否运行遵守统一策略 |
| 主窗口关闭但仍有组件 | 明确应用仍在运行，以及世界的运行状态 |
| 最小化或被其他窗口遮住 | 按运行策略继续；可减少绘制开销 |
| 退出应用 | 保存可保存状态，停止生态进程 |
| 电脑睡眠后恢复 | 恢复计时基线，跳过睡眠期间生态时间 |

O：关闭最后一个窗口是否退出进程，或仍驻留托盘。Codex 首轮须提出清晰建议，并让用户理解这会影响后台生态运行。不能用“关闭后还在运行”的默认行为替用户做隐含选择。

O：置顶、桌面层嵌入、鼠标穿透和自动启动属于待评估平台功能，不应以“桌面组件”一词推导为全部必做。

## 14. 多显示器与 DPI

UX-046（B）：布局以明确的逻辑坐标保存，同时记录必要的显示器标识和位置参考。逻辑尺寸、实际像素尺寸和生态世界尺寸分别管理。

UX-047（B）：显示器断开、分辨率变化或缩放比例改变后，窗口应回到可见区域，避免用户无法找回组件。

UX-048（B）：拖动窗口跨显示器时，文本、命中区域和像素场景分别按其规则调整。不能只让画面缩放而保留错误的鼠标命中位置。

建议实机检查：不同 Windows 缩放比例、双显示器、不同缩放比例之间拖动、主屏切换、外接屏断开、睡眠恢复。具体支持范围和限制记录在测试报告中。

## 15. 反馈、可访问性和诊断

- 主要操作提供可见反馈，颜色之外还要有文字或形状提示。
- 键盘焦点可见；弹出面板、列表和输入框不丢失焦点。
- 输入单位明确，非法数值解释问题并保留可修正内容。
- 操作失败指出当前状态，不把失败结果显示为成功。
- 重要信息可以从状态面板重新查看，避免只依赖短时通知。
- 动效与装饰可调低；生态推进与视觉动画开关分开。
- 诊断面板明确显示世界身份、模拟时间、运行状态和数据是否来自试运行。

## 16. 分阶段交互验收

M0 只验证基础显示、双视图、生命周期和毛玻璃覆盖能力。M0 的覆盖切换或样板示意不等于完整的鼠标离开计时、焦点协调和组件布局体验。

### 16.1 M1 林下闭环必须验证

1. 从林下预设创建独立世界。
2. 选中一块石头，拖动时显示预览，提交后原位置与新位置的空间属性更新。
3. 撤销并重做，恢复对应的完整编辑结果。
4. 进入运行，观察环境和鼠妇状态的后续变化。
5. 通过最小调试入口创建完整试运行副本并整体加速，丢弃后原世界保持原状态；本阶段不要求完整采用和另存界面。
6. 保存并退出，重新打开后恢复个体、资源与时间；现实昼夜按规则过渡。
7. 将同一世界显示为大窗口和小组件，确认只推进一份模拟。
8. 检查基底移动/移除、真正附着物及表面动物的位置约束，确认提交失败和撤销不会遗失个体或资源。

### 16.2 M3 集成必须验证

1. 完成试运行的采用、丢弃、另存与来源冲突反馈，采用后恢复正式运行意图、日常倍率和渐变现实同步。
2. 完成鼠标离开延迟、毛玻璃时钟、返回恢复、键盘焦点及编辑期间抑制覆盖的完整状态机。
3. 完成独立时钟、环境组件、自由摆放和叠放布局，恢复布局后世界绑定正确。
4. 完成两主题已声明的季节视觉阶段及其状态映射，明确尚未提供的季节内容。
