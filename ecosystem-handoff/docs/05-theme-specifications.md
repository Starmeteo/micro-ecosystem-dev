# 林下与浅水池塘主题规格

版本：交接草案 v0.1。状态标记沿用 [生态模型说明](04-ecology-model.md)：D 为用户明确决定，B 为当前设计基线，O 为需要研究、校准或进一步设计的事项。本文件给出内容模型和实验设计，不提供未经校准的“稳定养殖配方”。

## 1. 两个主题的共同约定

**D-THEME-01**：首版提供林下与浅水池塘两个主题，每个主题包含一个典型预设，用户可以修改预设创建新世界，也可以自由搭建。主题预设同时承担开发中的固定测试环境角色。

**B-THEME-01**：预设分为面向用户的典型环境与开发用压力场景。压力场景不要混在默认主题推荐中，让用户误以为这是适宜的初始配置。

**B-THEME-02**：世界具有自己的气候；现实同步仅影响配置允许的外部目标。两个世界的初始条件、当前状态、季节和随机进程互相独立。

**B-THEME-03**：候选生物组合先以功能角色组织，精确物种和数值由后续研究确定。一个主题中的生物应在所选范围内具有可共同验证的环境需求。不能因为每种生物单独有论文，就宣称整组必然长期稳定共存。

**O-THEME-01**：世界物理尺寸、初始数量/密度、底材深度、气候曲线、昼夜过渡时长和目标运行时长待校准。开发者先给出有依据的初值与试验记录；只有改变体验目标的选择才提请用户判断。

## 2. 主题、预设与世界的数据关系

| 对象 | 内容 | 版本语义 |
| --- | --- | --- |
| 主题定义 | 合法材料、候选物种、气候与边界能力、允许的编辑工具 | 主题版本固定其支持的模型语义 |
| 物种/功能群定义 | 参数、食物关系、阶段和视觉关联 | 定义 ID 与版本可追踪，不静默改旧世界 |
| 典型预设 | 布局、初始资源、生物组成、输入过程、默认观察视角 | 用作创建世界和回归试验的可重复起点 |
| 世界实例 | 从预设实例化后的实际状态与历史 | 每个世界独立运行，拥有完整随机状态 |
| 压力场景 | 基准预设加一组受控变化 | 固定变化、观测量和预期性质 |

“从预设新建”重新初始化世界；“复制当前世界”复制当前年龄、资源、随机状态和待处理过程。两者命令及 UI 名称需要区分。复制当前世界和创建试运行副本都生成新的 worldId；实体完整身份为（worldId，entityId），允许深复制相同 entityId 和随机状态值，但禁止共享可变对象或同一个随机生成器实例。

预设契约至少包含以下字段组：

- identity：稳定 ID、名称、主题 ID、预设版本、内容定义版本、模型版本。
- geometry：真实空间单位、区域与表面、水域连通、物件模拟属性。
- climate：世界气候方案、季节起点、光照节律配置和允许同步的现实目标。
- boundaries：降雨、补水、排水、落叶、气体交换、无机碳供应等过程及其来源。
- resources：土壤含水量、初始水量、有机物、可利用 N/P、初始溶氧等。
- life：个体/植株初始状态、斑块和种群组成，以及所有资源的初始归属。
- reproducibility：初始随机种子、固定测试驱动引用，以及初始化算法版本。
- view：推荐构图、相机、前中后景关系和缩放范围。
- validation：适用范围、初始化校验结果、校准状态和已有试验记录。

具体格式由架构文档统一。本文件字段是契约草案，不能被误认为已经存在并可直接运行的 JSON 数据。

## 3. 林下主题

### 3.1 场景定位

工作名称为“苔藓与枯叶的林下切片”。画面中可观察到苔藓、少量蕨类、枯叶、石头、朽木与鼠妇活动。主题强调潮湿程度、遮蔽、空间可达性和枯落物循环。

建议典型构图留出一段可观察的地表活动区域，周围以植被和木石形成层次。具体素材比例由视觉样板确定；生态物理面积与画面留白分别处理。

### 3.2 候选成员与开发顺序

| 功能角色 | 候选与选择状态 | M1 林下最小闭环 | 完整首版目标 |
| --- | --- | --- | --- |
| 地表生产者 | 一种苔藓或明确的苔藓代理类型，精确物种 O | 水分状态、基础生物量与覆盖反馈 | 受光/水/养分限制的生长、衰退与斑块扩展 |
| 小型维管植物 | 一种小型蕨类，精确物种 O | 可暂只用于受控的植株状态验证 | 植株生长、吸收、损伤和组织凋落 |
| 主要碎屑消费者 | 一种陆生鼠妇，精确物种 O | 个体身份、移动、觅食、躲藏和摄食账本 | 生命阶段、繁殖、死亡与压力响应 |
| 小型消费者 | 跳虫功能群，精确物种/群体模型 O | 可后置，不影响首个石头反馈验收 | 区域种群、指定食物、生命阶段或繁殖反馈 |
| 分解者 | 腐生真菌/细菌功能群 | 区域底物利用、简化矿化与生物量 | 分组响应与资源竞争；仍不按每个微生物绘制 |

分期约定：M1 同时提供最小试运行副本、整套模型加速与丢弃恢复，用于验证上述闭环。M2 的“首版生态内容补全”承接林下完整生命周期、跳虫、植物过程，以及林下和池塘的季节驱动与参数校准；M3 完成试运行采用/另存及完整交互流程。表中可后置到完整首版的生态过程不因此从交付目标中删除。

物种选择时应比较可获得参数、生命阶段资料、所选气候适用范围、可表现的行为和素材制作成本。两种鼠妇的实验数据不能未经说明拼成一个“真实物种”。若采用代理功能型，名称和说明应明确。

### 3.3 土壤、覆盖与边界

每个生态区域至少包含土体容量、含水量、养分、有机碎屑和覆盖关系。微地形与基底定义决定水分输入、输出和可通行条件。

石头和木头的遮阴、附着面、躲藏空间与阻挡关系分别定义。一次移动会改变旧位置和新位置；不可只修改精灵坐标。

附着关系采用 B 默认：明确 attached 的苔藓、生物膜等随基底移动；删除基底时附着物一并外部移出并原子记账。只是站在表面的动物不属于 attached；操作造成其无合法站位时拒绝整批修改并提示先安置，不暗中删除。撤销恢复基底、附着关系和全部资源变化。池塘中的附着资源也使用同一规则。

林下外部空气温湿度作为该世界气候的边界输入。土壤水分由降水/浇水、蒸发、吸收、排水及已有输运规则推进。首版若不计算林下局部空气流动，就只显示边界空气湿度和实际土壤水分，不给每块土编一个精确空气湿度。

预设允许外来枯落物时，需注明来自场景之外的林冠并记录输入量。关闭这一输入后，环境仅依赖现有库存和已经实现的植物凋落继续发展。

### 3.4 关键反馈与可观察行为

| 干预或变化 | 模型路径 | 用户可观察结果 |
| --- | --- | --- |
| 移动石块 | 覆盖/遮阴/通路变化 → 局部环境速率变化 → 动物评价位置 | 部分动物选择新的停留位置；旧位置条件也发生变化 |
| 增加落叶 | 显式有机物输入 → 食物/分解底物增加 → 生物量与矿化变化 | 摄食和分解事件、碎屑量与生物状态变化 |
| 停止外来水输入 | 水分供给变化 → 含水量、植物与动物压力变化 | 依照物种与条件表现活动、增长或损伤变化 |
| 增加动物 | 个体及身体物质输入 → 共同食物竞争 | 储备、摄食分配和后续生命状态改变 |
| 植物凋落或动物死亡 | 活体资源转入碎屑 → 后续分解 | 活体减少且碎屑与相关资源收支对应 |

这些是有条件的机制预期，不保证任意一次石头移动都让生物变好，也不要求每个个体作出同样动作。鼠妇微气候研究可支持响应方向，具体曲线仍需选择物种后校准。[原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4525041/)

### 3.5 林下测试环境

| 场景 ID | 基准与变化 | 观测量 | 验收性质 |
| --- | --- | --- | --- |
| FOREST-BASE | 固定布局、初始资源、种群和输入序列 | 水量、C/N/P、活体、摄食、事件 | 可复现，无未解释资源漂移；稳定范围由校准记录给出 |
| FOREST-ROCK | 基准副本中移动一块石头 | 旧新覆盖、蒸发/含水量、路径与行为 | 修改通过同一空间模型生效，恢复存档后结果延续 |
| FOREST-DRY | 降低或停止外部水输入，其他保持 | 含水、损伤、摄食、储备 | 不发生隐藏补水；越界或生物损伤有依据 |
| FOREST-FOOD | 关闭外来枯落物或提高消费者需求 | 食物、储备、排出物、生物量 | 食物竞争和消耗一致，繁殖不凭空补充个体 |
| FOREST-RECOVERY | 在受控缺水程度后恢复输入 | 含水、损伤与生长恢复 | 当前含水与损伤分开；恢复遵守物种模型 |
| FOREST-RESUME | 任一步边界保存，跨现实时间重开 | 全部生态状态、随机状态、昼夜过渡 | 无离线推进，过渡不直接覆盖土壤或生物状态 |

## 4. 浅水池塘主题

### 4.1 场景定位

工作名称为“水草与附着生物的浅塘”。包含可观察的水面/岸边、石木附着面、水草和小型水生动物。首版只实现能够解释其变化的有限水质过程。

默认生态计算采用每个连通水域充分混合。画面上的前后深度、水中遮挡和附着位置不等于已经实现分层温度或局部氧梯度。

### 4.2 候选成员与食物关系

| 功能角色 | 候选与状态 | 资源/行为设计 |
| --- | --- | --- |
| 沉水生产者 | 金鱼藻 Ceratophyllum demersum 是候选，最终物种 O | 作为无根沉水候选时，从水中获取已建模营养，不编造土壤根系吸收 |
| 附着生产者 | 明确的一类可食附着微藻/功能群，具体组成 O | 生长于表面，与消费者、光和养分形成反馈 |
| 悬浮生产者 | 一类明确可食的悬浮微藻，具体组成 O | 参与生产、营养竞争、遮光和水蚤食物供给 |
| 主要动物 | 米虾 Neocaridina davidi 是候选 | 重点摄食指定附着生物膜与可用碎屑，按个体表示 |
| 悬浮消费者 | 水蚤，Daphnia magna 可作研究候选 | 摄食已声明可食的悬浮资源，按种群/年龄组表示 |
| 分解者 | 区域微生物功能群 | 利用有机底物、增长、矿化与耗氧，避免与生物膜重复计账 |

金鱼藻无根与其水中营养竞争机制可见[该原始研究](https://www.frontiersin.org/journals/plant-science/articles/10.3389/fpls.2022.963579/full)。该研究包含首版尚未实现的 pH 等因素，因此不能拿本项目简化版本宣称完整复现其生态结果。

米虾在特定生物膜培养条件下完成生长繁殖的研究支持将生物膜列为食物，但不支持把任意附着物设为无限、完整营养的饲料。[原始论文摘要](https://agris.fao.org/search/en/records/65df4cd8b766d82b1801181d)

水蚤摄食效果与实际食物群落有关。一个野外群落实验中，其对藻类的控制能力存在明显限制；首版应声明可食微藻类型，不做万能清水生物。[原始研究](https://limnetica.info/pt/zooplankton-grazing-natural-algae-and-bacteria-under-hypertrophic-conditions)

### 4.3 环境与水量

每个水域记录水量、几何关系、温度、溶解氧质量、可利用 N/P、悬浮资源、底部碎屑及附着资源所在表面。所有浓度从质量和体积导出。

水量变为零时，转入干涸状态，停止不存在水体中的溶解过程。剩余物质保留到定义的湿底/干底残留库或显式导出，不能因除以零而删除。再次加水时是否溶解、溶解多快是需要声明的过程；首版可限制不支持的干湿交替操作并提示。

水域编辑采用以下首版建议，并在 Codex 审查报告中确认范围：

| 操作 | 当前范围与状态 | 必须保持的语义 |
| --- | --- | --- |
| 新建预设包含多个独立水域 | B：允许作为初始化结构 | 每个水域独立初始化水量与资源，不共享化学状态 |
| 已有世界调整水域形状但不改变连通拓扑 | B：首版优先支持 | 保持已有水量，按几何重新求水位；空间不足须显式处理或拒绝 |
| 已有世界动态分池/合池 | O：由 Codex 审查是否后置，未承诺首版实现 | 支持前拒绝改变连通拓扑的批次并说明原因；若实现则定义守恒的水量、溶质和生物归属转移 |

不能用合并两个世界的状态来冒充同一世界内的水体连通。自由搭建的范围应由这些可操作规则表达，避免向用户展示能够提交但没有资源处理语义的工具。

水温采用可检查的简化热收支或等价温度响应。进水温度不同、蒸发和水量变化时，要保持所选模型的内部一致性。热量未入账时，不宣称完成严格能量守恒模拟。

### 4.4 氧、营养与生物反馈

可利用 N/P 从输入、矿化等来源进入环境；水草、藻类和微生物按各自过程转移营养。悬浮藻和水草可以竞争光与营养；遮光系数和资源利用曲线需要校准。

氧气由光合、水气交换和进出水等过程增减，已建模生命活动消耗氧。需要氧的过程受供给约束，避免某个过程导致负溶氧。光合作用与呼吸等收支机制可参照 [EPA 溶氧资料](https://www.epa.gov/caddis/dissolved-oxygen)。

没有实现局部氧梯度时，不让米虾因为“水池右边氧更多”而移动；可以按整体氧状态改变物种适用的生理或行为响应。具体响应须由物种资料和模型版本说明。

界面只显示已计算的温度、水量/水位、溶氧、简化可利用 N/P 与生物/碎屑状态。完整氨毒性、pH、硝化和沉积物化学属于后续版本。省略硝化耗氧会限制高氮负荷预测，见 [EPA 氨资料](https://www.epa.gov/caddis/ammonia)。

### 4.5 池塘测试环境

| 场景 ID | 基准与变化 | 观测量 | 验收性质 |
| --- | --- | --- | --- |
| POND-BASE | 固定一个连通水域、气候与初始生物 | 水量、O₂、N/P、各生物与有机物库 | 可重复，所有变化有过程来源 |
| POND-DIEL | 固定相同温度等条件，切换有光/无光输入 | 光合贡献、呼吸贡献、氧库存 | 无光时无光合贡献；无额外重复夜间耗氧 |
| POND-ORGANIC | 在基准副本加入已知组成的有机物 | 输入账本、微生物、耗氧、矿化 | 碎屑不会被“清洁”功能直接删除，O₂ 非负 |
| POND-FOOD | 分别减少悬浮食物与附着食物 | 水蚤/米虾的摄食、储备与种群 | 食物选择匹配定义，各资源只计一份 |
| POND-EVAP | 仅启用指定蒸发，再执行加水/排水 | 水量、溶质总量与浓度 | 按声明过程保留/移出物质，浓度换算正确 |
| POND-ISOLATED | 两个不连通水域，仅向 A 输入 | A/B 独立库存 | B 无隐式污染或共享资源 |
| POND-SCARCITY | 限定供氧或加大已声明需求 | 实际氧分配、压力、死亡、碎屑 | 有限供给下自洽；超出模型适用范围时明确报告 |
| POND-RESUME | 保存、关闭、夜间重开 | 生态状态与昼夜过渡 | 恢复瞬间库存不跳变，后续通过过程响应 |

## 5. 模型结果怎样进入观察界面

| 观察内容 | 合法数据来源 | 表现约束 |
| --- | --- | --- |
| 生物个体信息 | 该实体权威状态 | 展示真实年龄和阶段；推断性描述注明性质 |
| 种群数量 | 群体状态 | 画面抽样数量与总数分开 |
| 植物覆盖 | 斑块面积与生物量关系 | 覆盖扩大有模型依据 |
| 水体透明度 | 已建模悬浮资源及选定视觉映射 | 颜色与浑浊程度是呈现近似，不等同水质全貌 |
| 观察记录 | 实际发生的事件和通量汇总 | 可展示“食物减少、摄食不足、储备下降”的记录，不凭结果编造唯一原因 |
| 健康提示 | 有明确定义的派生规则 | 点击可查看参与因素、模型版本和未覆盖范围 |

预设不能以“永远平衡”为验收目标。验收的是行为可解释、资源一致、在声明的适用范围与初值下具有已测的表现。生态变化允许偏离初始构图，用户可以通过编辑、检查点或新建世界处理。

## 6. 交给 Codex 的内容补全清单

以下多数属于研究与工程工作，不应逐条询问用户：

1. 选择每个功能角色的精确物种或明确的代理功能型，列出取舍与资料可得性。
2. 为每种生物建立温湿度、食物、生长、繁殖、代谢和元素比例参数的来源记录。
3. 为两个主题提出实际空间范围、初始密度和资源库存，并说明这些值处于“实验默认”还是“已校准”状态。
4. 固定基准预设版本、随机种子和驱动序列，制作压力场景及观测脚本计划。
5. 为严重缺氧、干涸、动态合池/分池等边界情况提出首版支持范围与合理失败行为。
6. 选择有代表性的场景和模拟时长开展步长收敛、守恒误差及灵敏度检查。
7. 对比大窗口与小组件的可读性；实体和资源数据必须保持一致。

需要用户判断的问题应集中到产品体验层：例如校准发现典型预设在很短的观赏时间内就持续衰退，是否要改变该预设的边界输入或初始配置；以及首次发布对自由地形编辑开放到何种程度。允许死亡的工作基线不因这类问题重新全部讨论。先指出已有决定及推荐处理，不把所有默认值重新交回用户。

试运行采用结果时保留副本已推进的生态状态、模拟时间、随机状态和当前环境节律；正式世界的 worldId、原运行意图及日常运行配置保留，试运行的加速和实验驱动不自动成为正式策略。切回日常驱动以当前状态连续过渡，基线冲突检查见架构合同。

首轮 Codex 只审查这套资料及其可实现性，输出缺口、建议和必要的集中问题。收到明确开始开发授权后，先完成包含最小试运行的 M1 林下闭环，再完成 M2 池塘与首版生态内容补全，以及 M3 完整试运行、组件和工作区体验。
