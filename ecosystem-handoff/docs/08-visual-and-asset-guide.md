# 视觉方向与素材制作规范

版本：审查资料 v0.1  
日期：2026-11-24

## 1. 视觉目标与参考资料

用户希望采用精细、具有自然空间感和光照氛围的像素插画风格。画面以精心布置的主要视角为中心，能够长时间欣赏，并在缩成桌面组件后仍保留层次与识别度。

用户提供的九张参考图原样整理在 references/originals，逐图编号和文件映射见[参考索引](../references/README.md)与[机器可读索引](../references/manifest.json)。美术工作应同时检查原图和本规范，不能只读取文字摘要后宣称已理解画风。

状态说明：D 为用户明确方向；B 为建议的工作基线；O 为需样板验证或选择的细节。原图中的手机状态栏、画面旋转、截图压缩等属于参考载体，不是产品视觉元素。

## 3. 画面的共同语言

### 3.1 像素具有结构

VIS-003（D/B）：像素块应服务于形体、材质和明暗。叶片、石块、木头、虾体或鼠妇的像素安排需要表达各自的轮廓和结构。

纹理应先遵循物体的大形与受光方向，再增加少量细节。随机噪点、均匀撒点、粗矩形叠放或全屏像素化滤镜只能作为临时占位，不能视为已达到参考图质量。

### 3.2 整体明暗先于局部细节

VIS-004（B）：场景需有可识别的主光、主要明暗分组和视觉焦点。缩小观看时仍能辨认地形、主要植丛和动物活动区域。

不要求每个位置同样清楚。暗部、遮挡和留白可以帮助形成空间；工具模式可提供选中轮廓和对象列表，保证编辑可用性。

### 3.3 配色按主题组织

VIS-005（B）：各主题维护自己的调色关系，至少区分背景、主材质、阴影、高光、生物强调色和界面颜色。

林下方向可以围绕苔藓绿、湿润土色、木色和柔和光照组织；池塘方向可以围绕水体青绿或蓝绿、植物绿、底部色与少量生物强调色组织。具体色值要从样板中确定，不能只用颜色名称替代视觉核对。

颜色数量不强制复古硬件限制。明暗色块之间应有秩序，避免每个对象使用互不关联的独立渐变。

### 3.4 生态画面与工具界面分别设计

VIS-006（B）：像素场景与编辑器文字、表单、按钮不必使用同一渲染分辨率。工具界面以可读、可操作为先，选择与布局辅助信息尽量克制。

用户尚未要求所有 UI 都采用复古游戏控件。正式 UI 皮肤应在样板里与场景共同检查，保留清晰文字与焦点反馈。

## 4. 构图与空间层次

建议按以下职责组织可拆分场景：

| 层 | 视觉职责 | 与模拟的关系 |
| --- | --- | --- |
| 远景与背景 | 提供大色调、环境方向和空间延伸 | 可包含明确标注的纯装饰部分 |
| 基础地形/水域 | 定义主要可观察空间 | 映射地表、水域和实际尺度 |
| 中景实体 | 石块、朽木、主要植丛与可活动表面 | 通常具有模拟身份与空间属性 |
| 生物 | 表现个体或群体代表 | 读取权威世界状态 |
| 前景遮挡 | 形成包围感、深度和局部节奏 | 参与模拟与否由资产定义明确 |
| 氛围与光照 | 光斑、水面变化、环境色和昼夜 | 关键变化读取环境状态，装饰动效独立标注 |
| 工具与组件覆盖 | 选择提示、时钟、状态信息 | 不修改物理空间 |

VIS-007（D/B）：主要视角固定，不依赖自由三维相机。允许画面局部缩放、平移和观察方式调整。

VIS-008（B）：显示层次与生态高度分开。相同的前后绘制顺序不自动意味着相同的地形高度、遮阴或水深。

VIS-009（B）：布置素材需要具有明确的锚点、承托关系与接触阴影方案。移动石头后，旧位置和新位置都要更新相关表现，避免残留阴影或与地面脱离。

基底上的苔藓、生物膜等如被定义为真正附着，应随基底移动。仅站在表面上的动物使用独立位置与合法性规则；它们不能因画面层次相邻就被当作附着素材一并删除。移动与移除的批次语义见交互文档。

## 5. 像素密度与缩放

O：场景的逻辑像素密度尚未锁定。首个视觉样板应比较至少两种细节密度，检查动物轮廓、植被纹理、大窗口放大和小组件缩小的效果。

VIS-010（B）：在像素场景中维护统一的尺度规则。相同真实大小的动物或材质不能因为来自不同资产包而使用互不兼容的细节密度。

VIS-011（B）：场景像素的缩放与纹理采样需要显式配置；默认以保留清晰像素结构为目标。最终策略在真实窗口尺寸与 DPI 下验证。

VIS-012（B）：整数缩放、留边、裁切和非整数缩放会产生不同构图结果，选择应由样板和实际使用尺寸决定。界面必须保持比例正确，不能为了填满组件任意拉伸生物。

VIS-013（B）：文字和操作控件保持独立可读性。高 DPI 下同时检查画面、文字、命中区域和窗口尺寸，不能只截取场景区域验收。

## 6. 动画与生态状态

动作可以具有细节与节奏，但主要行为必须与世界状态一致。

| 状态或过程 | 动画与画面建议 |
| --- | --- |
| 动物移动 | 根据权威位置和方向播放对应动画，显示层做平滑插值 |
| 觅食与摄食 | 在合法食物位置表现停留和相关动作，资源扣除由内核决定 |
| 休息与躲藏 | 进入有效遮蔽区域，使用适合物种的低活动表现 |
| 植物生长 | 根据生物量或生长阶段切换、组合结构，避免只整体放大图片 |
| 植物损伤 | 对应已建模损伤状态，颜色与结构变化可解释 |
| 水位变化 | 水面、岸边和露出部分与实际水量/地形一致 |
| 昼夜变化 | 色调、亮度、高光和投影按环境节律缓慢变化 |
| 悬浮藻类变化 | 在模型支持范围内影响透明度与水色 |
| 装饰性微动 | 小幅水波、光斑、摆动；不额外创造生态资源 |

VIS-014（B）：视觉动画不能负责判定死亡、摄食、繁殖或资源变化。窗口帧率变化不影响这些结果。

VIS-015（B）：微小种群可以抽样绘制，但统计数据来自模型，界面避免把绘制数与种群总数混用。

VIS-016（B）：动画帧数、周期和方向数在素材试制后确定。首个闭环先保证静止、移动和必要转向的连贯性；后续再补充细节状态。

VIS-017（B）：装饰动效可降低或关闭，生态过程仍按运行策略推进。昼夜变化与毛玻璃切换应避免突兀闪烁。

## 7. 光照与水体表现

### 7.1 光照

VIS-018（B）：先建立统一的光照方向和材质明暗，再增加局部光斑。石头、叶片、木头和动物不能各自看起来来自完全不同的光源。

艺术表现可简化真实光传输，但场景中的重要遮阴关系应与生态层协调。纯装饰的光斑不应被当作精确的光照能量测量。

昼夜变化可以组合环境色、局部明暗和高光强度。夜晚仍需要保留必要层次；是否提供额外观察照明属于可评估体验，不默认加入会改变生态的光源。

### 7.2 水体

VIS-019（B）：池塘样板优先验证透明度、底部可见性、植物遮挡、深浅关系和水面高光，确保这些效果在缩小后仍然清楚。

水体不必使用复杂三维流体模拟来实现像素氛围。首版的真实水流、局部氧梯度和折射物理范围由生态及架构文档决定，视觉效果不能暗示不存在的模拟能力。

水中漂浮粒子、气泡和波纹应有清晰用途。若气泡仅作装饰，不应给用户造成“系统正在补充氧气”的误解。

## 8. 原创素材的最小交付单元

VIS-020（B）：正式资产按可重复布置、可替换与可组合的单位制作。每个资产至少记录：

| 字段 | 用途 |
| --- | --- |
| asset_id / revision | 稳定身份与素材版本 |
| display_name / theme | 用户可读名称与适用主题 |
| source_path / format | 可编辑源文件与运行时导出文件 |
| logical_pixel_size | 图像逻辑尺寸 |
| physical_size / scale_rule | 实际尺寸与画面尺度之间的关系 |
| anchor / pivot | 放置锚点、旋转与动画参考点 |
| facing / variants | 支持方向、镜像条件和变体 |
| draw_layer / depth_rule | 绘制层次及遮挡规则 |
| simulation_binding | 对应物种、材料、表面或仅装饰身份 |
| occupancy / surface_metadata | 模拟占地与活动表面；与图像透明边界分开 |
| attachment_binding | 真正附着的基底身份和相对位置；与动物暂时站立关系区分 |
| animation_states | 状态、帧序列、时长及切换条件 |
| palette_group / lighting_notes | 主题配色与光照约束 |
| provenance / usage_status | 来源、作者/工具、使用范围记录与待核实状态 |

阴影遮罩、法线贴图或更复杂光照数据可以作为后续可选字段，不应让首版所有素材都承担未验证的制作负担。

VIS-021（B）：精灵表和图集需要检查边缘、透明度、帧边界和缩放后的采样表现。预览通过后再进入场景批量使用。

VIS-022（B）：生态占地、碰撞、可附着表面和遮阴信息由数据定义保存。它们可以与美术素材配套制作，但不应只藏在一张无法解析的图片里。

## 9. 素材生产与来源记录

参考图保留原样、原始尺寸和文件校验信息。对旋转截图，可由资料浏览器提供观看方向说明；任何阅读用衍生图与原图应分别标记。

素材来源记录只陈述已知事实：

- 用户参考图：用户在本次讨论中提供；画师姓名与授权范围如未给出，记录为未提供。
- 原创项目素材：记录制作者、工具或制作方式、日期、版本和源文件。
- 第三方素材：记录来源链接与实际许可条款位置。
- 临时占位：显著标记用途，不能在交付验收中冒充正式素材。

VIS-023（B）：参考资料和产品资产分开存放。资料包包含参考图，不等于已经确认可以把原图直接打包进产品。

O：正式素材采用手工、程序辅助或图像生成辅助的比例，需要结合样板质量和可编辑性确定。Codex 首轮给出制作路线和最小资产清单，不在审查阶段大量生成。

## 10. 首个林下视觉样板

建议优先制作一张可以拆分的林下样板，包含：

- 一组整体色调与前中后景关系。
- 土壤或落叶地面。
- 一块可移动石头及其接触表现。
- 一段朽木或其他构图支撑物。
- 一片具有边缘变化的苔藓。
- 少量鼠妇及基本动作。
- 白天和夜晚两种环境表现。
- 大窗口与小组件的实际尺寸预览。
- 选择轮廓、拖动预览和毛玻璃时钟覆盖的示意。

其中额外植物可以随样板需要添加，但不要求首个样板立即覆盖全部物种与生命周期。

本节样板属于 M0：毛玻璃时钟可以作为能力实验和状态示意，完整离开计时及焦点交互在 M3 验收。M1 要把必要素材连接到真实林下状态；M2 补齐相应生态内容，M3 集成两主题已声明范围的季节视觉。

VIS-024（B）：样板同时提交静态画面、短动作预览和素材拆分说明。只提交一个漂亮但无法编辑的完整背景，不能证明编辑器素材方案可行。

## 11. 完整首版素材范围

| 主题/系统 | 核心资产 | 需要根据模型补充的状态 |
| --- | --- | --- |
| 林下 | 土壤、落叶、石块、木头、苔藓、候选蕨类、鼠妇及必要小型种群表现 | 生长、损伤、生命阶段、湿润与干燥差异 |
| 浅水池塘 | 底材、岸边、石木、沉水植物、附着食物表现、米虾与水蚤代表表现、水面 | 水位、透明度、植物阶段和相关生物状态 |
| 组件 | 时钟、状态文字、焦点与编辑控件、毛玻璃覆盖 | 悬停、计时、覆盖、编辑、错误提示 |
| 主题与预设 | 缩略图、说明图、素材分类标记 | 配置版本与内容缺失状态 |

季节视觉内容在 M3 按明确阶段集成，并记录已经支持的主题和变化。生态模型有季节驱动，不自动意味着所有素材都已具备四季变体。

## 12. 视觉验收方法

### 12.1 静态对照

- 检查参考图与样板之间的像素组织、明暗层次、配色关系和细节密度。
- 将样板缩到实际组件大小，检查主要生物、地形和视觉焦点。
- 放大检查轮廓、透明边缘、纹理拼接与重复素材痕迹。
- 检查昼夜变化后的层次和可读性。

### 12.2 动态对照

- 动物移动与停留连贯，不依赖每帧随机抖动制造活力。
- 对象前后关系正确，无明显穿插或悬浮。
- 移动物件后，接触关系与旧位置表现同步更新。
- 毛玻璃出现和消失平滑，覆盖布局与鼠标交互一致。
- 渲染降频或隐藏后恢复，读取最新状态而不补播所有旧帧。

### 12.3 工作区与实机对照

- 检查小组件、大窗口和不同纵横比。
- 检查高 DPI 和跨显示器拖动后的文字、像素场景与命中位置。
- 检查时钟叠放后是否遮住重要观察区域，以及布局编辑是否清晰。

VIS-025（B）：验收记录必须区分艺术审查、浏览器/渲染检查和 Windows 实机检查。未进行的检查保持未验证状态。

## 13. 审查时应避免的误读

- 用“像素风”概括所有要求，忽略参考图的颜色和空间。
- 将原图中的人物、鱼种或水族馆建筑全都列入首版。
- 将整张参考图铺作背景后，把几只动画生物叠上去，声称已经实现可编辑生态场景。
- 以随机噪声、单调重复贴图或粗糙几何占位宣布视觉完成。
- 为了画面更热闹，添加不受模型控制的出生、摄食、死亡或资源效果。
- 调整窗口尺寸时改变世界物理尺度或生物数量。
- 把旧 HTML 操作草图当作正式美术参考或实际性能证据。

## 14. 视觉审查的输出

Codex 首轮应在审查报告中说明已经查看哪些原图，归纳共同视觉特征，指出素材拆分和缩放可能存在的问题，并提出首个样板的可执行资产清单。

若当前工具无法读取原图，应明确说明缺少的视觉核查，并先完成可进行的文档审查。不能声称看过未读取的图片，也不能据此直接展开正式素材制作。

原图可读后仍不需要逐个颜色或每个动画帧向用户提问。应把用户决策集中在样板风格是否贴近预期、实际观看体验和明显改变项目工作量的选择上。
