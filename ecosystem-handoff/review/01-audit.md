## 项目理解

用户在 Windows 编辑器里布置土壤、石木、植被和水域，放入生物，观察生物之间及生物与环境之间持续发生的反馈。移动石头应先改变遮阴、遮蔽和通行，随后影响局部水分及鼠妇的栖息选择。“真实”首先要求这些因果能追溯到生态状态和输入。画面以精细像素插画营造自然氛围，维持精心组织的主视角，用遮挡、比例、色彩和光照表现空间，可局部放大或平移观察。

完整首版有林下、浅水池塘两种主题，每主题至少一个典型预设，支持使用、修改另存及从空白搭建。每个世界有独立的生物、资源、随机进度和气候，同一世界可在大窗口和多个组件中显示，由 Rust 只推进一次。退出、系统睡眠、关机期间生态暂停，重开恢复已保存世界，昼夜驱动随后逐渐对齐配置地点的太阳时刻。独立时钟立即显示当下北京时间。常态小组件可以在离开一段时间后以场景内模糊覆盖显示时钟等内容，时钟也能独立创建、叠放或在可移动面板中自由摆放。

D-001～016 保留为已确认方向，包括暂定 Tauri 2、React 19、TypeScript、PixiJS 8、Rust。B-001～014 用于规划，例如应用存活时未暂停世界继续、日常 1:1、充分混合浅塘。O-001～009 保持待定，可研究或实验的事项由开发侧处理。需要取舍的建议与确认记录见 [02 问题与决定](02-questions-and-decisions.md)。[项目基线](../docs/01-project-baseline.md)

## 产品完整性与范围

02 PRD-006～008 与 05 D-THEME-01 给出了完整首版的创作入口。两个主题各交付至少一个典型预设，区分面向新用户的样例和开发压力场景。空白搭建要提供最小可用底材和合法性检查，可以告知用户某种组合的生态风险。尺寸、例示键位、动物数量和图上的物种均以各自证据范围为准。M1 只承诺从一个林下预设完成编辑、实质反馈与恢复，复用 M0 的基础小组件。保留完整首版在 02 §5/09 §7 的主题、自由搭建、多世界和布局要求。

## 生态模型与科学证据

- **状态与单位。** 主要鼠妇、虾按个体，苔藓、水草/附着藻按面积与生物量斑块，水蚤/跳虫按区域或阶段组，微生物按功能群，水土为环境单元。计数下降对应元素质量转移，显示抽样独立于计数。明确土体体积含水率和储水饱和度的区别，质量、体积、浓度分别存储或派生。统一 m、m²、m³、s 与各物质 mg，展示浓度 mg/L 为 mg/m³ 除以 1000。固定 C:N:P 仅作工程近似，限制元素不足时成比例缩小过程。连续量保留值与误差来源，水用 m³ 容差，元素用各自 mg 容差。覆盖、遮阴和可达性是三个可分别变化的量。
- **完整转移。** 先做逐过程表。每步从同一基线提出候选通量，按来源池聚合需求，使用固定顺序和确定分配。多底物过程的整笔投入及产出共同比例缩放。初期保守地让新产物下一步才参与竞争，暂不二次分配剩余量。用步长/半步和遍历置换检查收敛与偏差。摄食一次扣食物，分流为同化与未同化排出。维持代谢从实际储备扣除，死亡一次转入遗体或碎屑，矿化分别产生微生物增量、矿物养分与碳输出。人手投放、林冠枯落物、降水、蒸发、排水、气体交换都标识来源和去向。关闭输入时看不到隐式补员。固定物质账本不等于完整能量收支。
- **林下证据。** Dixie 等支持不同鼠妇物种在温湿度条件下的聚集及生理差异，实验空气相对湿度不能直接换成虚拟土壤含水曲线。Hassall 等支持枯落物与摄食碎化、分解的条件差异，摘要不足以给通用同化率或林冠输入。USDA 资料支持养分固定与释放，蕨类综述支持区分含水状态和复水后损伤，均不能直接给苔藓或鼠妇定值。M1 可用有标签的功能型，具体物种、尺度、速度与通量由开发侧查证并以敏感性试验决定。 [鼠妇原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4525041/) · [枯落物原始论文摘要](https://link.springer.com/article/10.1007/BF00378988) · [USDA Soil Biota](https://www.nrcs.usda.gov/sites/default/files/2024-05/Rangeland%20Soil%20Health%20Soil%20Biota%20SD-FS-85b%205-9-24.pdf) · [蕨类水分策略原文](https://academic.oup.com/aob/article-pdf/134/7/1139/59637108/mcae167.pdf)
- **浅塘边界。** 每个连通水体一组溶氧和可利用 N/P，各自独立。水深、受光、遮挡和附着位置仍可空间变化，生物的缺氧反应必须读同一水体的氧值。生物膜是对附着藻、微生物和碎屑等有归属库的聚合显示，摄食只扣实际组成。光合产氧，呼吸和有氧分解按氧供给限流，避免微生物耗氧二次收费和额外的“夜间扣氧”。严重持续缺氧可停止不适用过程并提示，省略硝化会漏掉相应耗氧，氨毒性、pH、硬度或完整水质无预测资格。O₂ 库以含过程源汇的收支验收。蒸发留非挥发溶质，排水按声明携出物，干涸保留定义的残余库并停算浓度，明确氧的外输去向。饱和值先选温压盐条件一致的权威公式，水气交换系数单独研究。 [EPA 溶氧](https://www.epa.gov/caddis/dissolved-oxygen) · [EPA 氨](https://www.epa.gov/caddis/ammonia) · [USGS 溶氧方法](https://water.usgs.gov/water-resources/memos/documents/WQ.2011.03.pdf)

## 架构与通信

Rust 内核是可无界面执行的纯规则，运行层管理世界串行写入、步进与检查点，Tauri 映射宿主事件和 IPC，React 管输入、工具和布局，PixiJS 只消费快照做绘制与插值。UI 可以画拖动预览，最终占据和资源由 Rust 校验。建议共享不可变定义，世界独立持有全部可变状态，试运行完整深复制。06 §3 的单写入者需覆盖用户双开程序，建议由单实例机制或数据目录写入锁保护，M1 首个真实世界前验证。 [Tauri 单实例插件](https://v2.tauri.app/plugin/single-instance/)

| 标识 | 语义与边界 |
| --- | --- |
| worldId 与 entityId | 世界与其实体的持久身份。新建、复制、临时分支产生新世界 ID，同一实体 ID 可以在不同世界出现 |
| runGeneration | 运行代次。重载、检查点替换、采用分支时更新。收到新代次的快照先取得对应全量基线，避免任意迟到消息把客户端切回旧状态 |

## 用户操作与生命周期

为 03 §8/§13 建议四个明确动作。取消拖动结束前端预览，撤销反转已提交的生态批次，结束编辑只解除编辑暂停，保存持久化当前完整状态。编辑租约关联世界、窗口和会话，组件布局拖动、覆盖时钟与相机走独立输入层。从世界 A 切到 B 时取消 A 的未提交预览并处理在途命令，已提交修改保留，并分别显示 A 的编辑和保存状态。应用级隐藏、恢复与退出通过托盘管理，隐藏所有窗口后，未暂停世界照常推进，恢复窗口读取最新状态。隐藏或遮挡可停绘制。结束编辑或系统唤醒均保留用户已有的手动暂停。

## 时间规则

07 §2/§4 的三种时间应各有权威来源。现实瞬间用于显示北京时间及计算配置地点的太阳相位。系统活跃计时提供可获准的经过时间，模拟累计只加完成的固定步。持久化的环境相位独立运行，由世界气候和现实目标按约定组合。比如 23:59 到 00:01 的相位差沿环形为 2 分钟。更换 Windows 时区本身不改变北京时间显示或地点日照。真实系统时钟回拨只重定向当前目标，不能在一帧消耗一小时食物。实际恢复时先显示保存态，世界可运行后再渐变。相位差恰好半周的纠偏方向要有明确规则和适度限速，避免大跳或回绕闪光。

普通忙碌积压限量补步，显示落后量。被手动或编辑暂停的时段不进入累计，睡眠时段按平台活跃时间与通知对照处理，恢复事件重复时只重基线一次。计划暂停时冻结尚未执行的余量，恢复再继续正常活跃计时。退出后从最后成功持久化步恢复，试运行按受控输入和整套过程共同加速。世界季节与现实日夜可以共存，建议世界时间控制季节性温湿、降雨和亮度包络，地点太阳事件提供昼夜相位目标。M1 实测已确认的 1:1 节奏，见 R07 和 Q4。

## 数据与存档

主题与物种/材料定义、创作预设、正在运行的世界、相机/视图和工作区布局分别存储或版本化。创建预设、从预设初始化和复制现在的世界必须提供不同操作。建议保存为预设时用预览确认布局与投放初始条件，并说明年龄、历史、资源初值和种子怎样生成。复制现状才保留年龄、完整随机状态和生态时钟。删除世界前列出受影响订阅和布局，保留可见的未绑定入口或明确移除，避免跳绑另一个世界。试运行采用在同一写入边界查 worldId、代次、编辑版本与 tick，冲突保留两边。成功采用后保留正式身份、暂停意图与日常驱动，续接相位，丢失回执时先对账再确认。保存采用结果须定义故障窗口，恢复时能识别旧检查点或已提交的新检查点。

## 开发计划与验证

09 M0 可交付一个小原型和证据集，Rust 核心、Windows 生命周期和可编辑视觉样板并行，对齐同一参考场景及坐标合同。先验证同输入复现、两视图和无视图一致、实际睡眠差异与检查点恢复，再用 M1 的完整林下状态复测。最小命令失败、幂等回执、世界隔离和旧订阅拒绝在合同与真实编辑出现时即验证，更全面的管理界面在 M3 补齐。M1 开发顺序先验收资源所有权、局部空间、数值和边界输入，再把鼠妇行为及画面接上。收支、固定输入反事实和真实 Windows 操作各有独立证据。任务与完成条件见 [03 实施与验收计划](03-implementation-plan.md)。
