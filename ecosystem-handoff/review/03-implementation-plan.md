# 修订后的实施与验收计划

2026-11-24 · 审查建议 · REVIEW_ONLY

依赖顺序为 **M0 原型基础 → M1 林下最小闭环 → M2 浅塘与生态补全 → M3 多世界与组件整合 → M4 首版验收**。M0 建立下一步可以复用的最小合同与实机证据。完整首版保留两个主题、自由搭建、常态组件和独立运行的多个世界。下表各项均为授权后的实施计划。

## M0 · 建立一条可以验证的原型路径

**输入**　确认审查结论和授权范围。本机 Windows 11 25H2 x64 是初始验证环境。现有交接包作为设计证据保留，正式工程建议在工作区创建，按职责分出 Rust 内核、运行层与桌面宿主。Q1 已确认三类无按钮窗口、托盘与隐藏全部后的运行规则，原型先验证。Q2 已确认北京时间与地点日照，M0 可用固定驱动验证时间合同。

### M0 合同和证据重点

- **计时。** 桌面钟将当前现实瞬间显示为北京时间。Windows 活跃计时源与电源消息由宿主送到 Rust，内核只拿模拟步长和明确的驱动。首轮比较墙钟时间与活跃时间，区分手动暂停、编辑暂停、S0 低电量待机、休眠、锁屏/息屏和实际可运行但处理忙碌。重复通知去重。普通积压限量分步处理并报告落后，退出后不读取未执行队列。用固定输入校对当前相位恢复、环形跨午夜、持续移动目标、系统时区切换和回拨。
- **IPC。** 每世界由一份 Rust 运行实例排队写入。定义世界 ID、运行代次、命令 ID、编辑版本、模拟步数、订阅 ID 与流序号的来源、作用域、更新条件、失效和重试规则。命令回执可对账，视觉路径可合并。客户端切换或重挂取全量。至少试两个观赏视图分别打开、关闭、再打开。应用进程独立于是否有视图。采用应用级单实例或数据目录锁，最迟 M1 引入真实用户世界前验证双开防重复写入。
- **数据与失败。** 定义检查点、索引、逻辑定义包与工作区各自归属。Windows 路径中，候选写入和刷新、正式发布、上一有效版本有独立步骤。恢复不根据文件名擅自加载半成品。故障注入记录实际成功边界。最小对账覆盖正常保存、保存失败和读旧代次。代表完整模型的版本迁移样本随 M1 建立。
- **视觉和环境。** 同一视角检查大窗、小窗、局部观察，比较昼/夜、遮挡、石头移动、方向动作与毛玻璃前后。组件测试尺寸先用约 320×200 CSS 像素，再从机上测可读下限。100%、125%、150%，有条件加 200% 和混合 DPI，记录鼠标命中、负坐标、多屏拔插。视图异步初始化和销毁均释放订阅与 GPU 对象，隐藏恢复读取最新全量。若应用内模糊有性能问题，先测降低模糊分辨率或复用缓存，保留覆盖交互与清晰时钟。
- **证据。** 固定场景和时间序列，记录 Windows build、CPU/GPU/驱动、WebView2、缩放档位、后端、实体/世界/视图数、前后台状态、IPC 大小及频率。比较 tick 耗时、帧耗时分布和输入触发到回执，报告中位与较慢尾部、空载/大窗/小窗/双视图、是否失去 GPU 上下文。当前机器无 S3。外接屏、较弱设备若缺，标记未验证并保存复测步骤。

**M0 完成条件**　目标 Windows 环境能复现启动，WebGL 基础路径与应用内覆盖可显示。视觉样板在大小窗可见、可拆、可移动且有人工评审。无视图、单视图与双视图步进结果一致，旧订阅和旧代次被拒绝。最小状态能保存、重开并恢复同一随机和模拟进度，有实际执行的文件回退用例。S0/休眠与普通延迟至少在目标可得模式有实测，失败威胁 D-011 时先解决计时路径再做 M1 生命周期。若某外围实验仅提供了候选缓解方案，将结果标为需修正并写明受影响范围。M0 毛玻璃用于能力验证，完整离开计时和布局在 M3。渲染或样板问题可与无界面验证并行修复。

### M1 验收的实际操作和对照

1. 从预设新建一份世界。加载初值后记录 ID、模型/内容、气候、主要池、鼠妇状态、完整随机状态与 tick。暂停进入编辑，分别演示取消、非法位置、有效移动、撤销与重做。鼠妇没有合法空间时拒绝整批。基底相关附着物状态、余额和身份应能逐条对上。
2. 从同一基线运行对照分支，固定驱动与种子，一边保持石头位置，一边只移动石头。检查旧新区域的遮阴、遮蔽、可达性立即改变。在可蒸发的条件下，继续记录水分、通量、鼠妇候选位置评分及多种子停留倾向。再加一个保持遮蔽只改水分的测试，避免把所有动物行为归因于石头。画面记录同时标注真实/试验倍率和经过时间。
3. 用 1:1 做一次可复现的短观赏，建议先记录 5～10 分钟作为观测窗口，再用受控试运行展示慢变量。允许效果小或出现反例，证据说明条件、差异和可观察程度。试运行与正常倍率在固定输入、相同步数下比较，再丢弃副本验证原世界未改。
4. 从托盘隐藏全部窗口，检查未暂停世界的模拟步数继续增加，手动或编辑暂停时保持原状态。重新显示窗口后读取同一世界的最新状态。从托盘保存退出，跨一段现实时间重启。同一个世界保持个体、资源、模拟时间和 RNG，第一帧恢复保存时的相位，时钟立即显示北京时间，后续光照按配置地点渐变。固定输入回放比较连续运行与保存恢复分支。检查真实 S0/休眠、北京时间跨午夜、系统时区切换、不同地点同一瞬间、高纬无日出或日落，以及未结束编辑的恢复。
5. 用零库存、高需求、改变遍历顺序、将步长减半和关闭外界输入检查收支与稳定性。给每种实际追踪资源预先记录绝对/相对容差，报告偏差趋势。存档覆盖截断、磁盘占用、模拟写满、旧检查点、索引丢失、写入中终止与定义包缺失/不支持的模型版本。原件保留且错误能在界面识别。

建议把 05 的 FOREST-ROCK 与 10 的 FIX-FOREST-SHELTER 映射为同一对照数据，FOREST-RESUME 对应保存和 TIME 检查，其他 BASE/DRY/FOOD 以输入、条件与断言登记。M1 以 VAL-EDIT-001～004、VAL-TIME-001～012 的适用项、VAL-IPC-001～006 及合法运行干预的 007、林下 VAL-ECO 和检查点 VAL-SAVE 为主要验收锚点。

**M1 完成条件**　有可运行 Windows 闭环和独立验证记录。移动石头后旧、新位置的空间属性与水分、鼠妇反馈可解释，同一世界大/小窗口与保存恢复一致。调试副本能整体加速和丢弃。资源收支、原子失败路径、运行隔离与休眠应有实际证据。正常倍率观察缺乏明显反馈时先改善观测、参数取证与情景设计，并给 M2 的节奏取舍证据。

## M2～M4 · 保留完整首版

每阶段提交真实产物、输入和复现环境、预期与实际结果、未执行与失败用例。授权仅覆盖 M0 则在 M0 后停止。获得整体授权时可按上述依赖推进，遇到影响范围的新取舍或实测阻塞时再处理。正式开工范围以用户的明确指令为准。
