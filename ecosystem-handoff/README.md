## 这份资料交给谁

本资料供项目发起人和后续 Codex 开发会话共同使用。它把本次讨论中的产品方向、生态模型、编辑器、桌面组件、架构、视觉参考与验收方式整理在一起。文件可直接放进项目仓库，采用 UTF-8 Markdown；参考图保留上传原文件的字节内容。

**首次接收资料时只做审查。** 先找遗漏、矛盾、错误假设、需要用户取舍的事项，再给出结论与实施计划。审查无阻塞，并且用户明确授权开始后，才能进入 M0。资料内的任务清单、原型和建议都不构成开工授权。

## 用户怎样使用

1. 解压整个文件夹，不要只抽取部分文档或遗漏 references。
2. 将整个文件夹提供给 Codex，或放在 Codex 可以读取的本地工作目录。
3. 复制 [CODEX_REVIEW_FIRST_PROMPT.txt](CODEX_REVIEW_FIRST_PROMPT.txt) 的完整内容作为首次提示词。
4. Codex 应返回审查报告、需要用户决定的问题、实施计划和就绪结论。
5. 处理真正影响方向的问题后，明确说明授权范围，例如“审查结论认可，按确认的整体计划开始开发，先完成 M0”。若只授权 M0，则完成 M0 后再决定后续；若授权整个计划，Codex 可按里程碑继续。

## 项目核心约束

- Windows 桌面微缩生态项目，包含生态创作、运行观察和自由组合的桌面组件。
- 精细、具有自然层次和氛围的像素画面；以精心布置的固定主视角为主。
- 首版目标包含林下和浅水池塘；按主题选择预设，也可修改另存或自由搭建。
- 生物之间、生物与环境之间发生可解释的因果影响，资源有来源和去向。
- 世界互相独立。同一个世界被多个视图查看时，只运行一份模拟。
- 软件停止、电脑睡眠或关机期间不补算生态；恢复原状态后，昼夜目标平滑对齐现实。
- 每个世界保留自己的气候。现实同步不直接覆盖内部资源存量。
- 技术栈暂定 Tauri 2、React 19、TypeScript、PixiJS 8、Rust；具体版本需审查兼容性后固定。

## 阶段边界

交接包中的 D 表示用户明确决定；B 表示已接受作为当前规划依据的工作基线；O 表示仍需审查、选择或校准。B 可以由审查发现问题后调整，但不能无记录地改成相反方向。O 不等于必须把问题交给用户：普通技术选择由 Codex 研究和建议，影响产品体验或范围的取舍才集中提问。

第一版可用产品与第一个里程碑不同。首个闭环优先完成林下石头编辑、局部环境与鼠妇反馈、保存和恢复，随后扩展池塘、完整多世界和组件布局。阶段完成不能自动宣称整个产品已完成。

## 资料完整性

包内包含 9 张用户上传参考原图。原图身份按用户发送顺序编号；两个手机截图保持原始朝向，浏览页提供仅影响显示的旋转按钮。没有把参考图当作新的原创素材，也没有生成替代图。

所有生物参数、性能指标和兼容性状态按文档标注处理。该资料包不包含经过校准的生态引擎、已完成的正式美术或已经通过 Windows 验收的产品。

包内文件校验清单见 FILE-MANIFEST.json；图片校验以 references/manifest.json 为准。下载后无需依赖本次聊天才能理解主要需求。
